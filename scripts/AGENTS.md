# Утилиты проекта

## Использование

- Единая точка входа — dev.sh. Запусти его со справкой и выбери проверку, форматирование или генерацию.
- Допустимые действия и области Git находятся в checks.json и выводятся через check git-policy. Генерация веток и merge-сообщений использует тот же словарь и валидаторы.
- Для адресного входа в механизм проверок используй check.py со справкой. Точные режимы и параметры описаны самим инструментом.
- Внутренние реализации обслуживают эти режимы. Пакетные проверки задаются конфигурацией рядом со скриптами.
- Команды выбранной области проверяй также в её локальной папке scripts и манифесте.

## Разработка

- Перед новой проверкой найди существующий режим и его тесты. Повторяющуюся диагностику переноси в подходящий инструмент.
- Общие команды размещай здесь, специализированные — рядом с владельцем функциональности.
- Расширяй команды режимами при общей ответственности. Выделяй отдельный инструмент, когда его вход, жизненный цикл или назначение действительно самостоятельны.
- У команды должны быть название, назначение, случаи использования, входные параметры, режимы и результат. Показывай это через help и argparse, а рядом с кодом сохраняй однострочное модульное описание.
- Определяй пути относительно репозитория. Передавай команды массивами аргументов, сохраняй логи и возвращай ненулевой код при отказе.
- Используй Python-оформление из [backend](../backend/). Обращение к этой общей части не требует изучать код backend.
- Добавляй регрессию для нового режима, включая отказ, когда проверяемое условие нарушено.
