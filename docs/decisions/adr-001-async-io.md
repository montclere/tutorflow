# ADR-001 — асинхронный I/O backend

- Дата — 2026-11-24.
- Статус — принято.
- Связи — UC-001, BR-001, BR-002, BR-004.

## Контекст выбора

Identity и Scheduling станут образцами для следующих модулей. Первоначальный стек выполнял запрос целиком в пуле потоков FastAPI. После проверки шаблона владелец выбрал сквозную асинхронную модель для операций ожидания. Сейчас нужно определить контракты портов и владение подключениями до размножения модулей.

## Альтернативы

- Синхронные обработчики, SQLAlchemy Session и сетевые клиенты в пуле потоков. Это сохраняет первоначальную реализацию, но занимает поток на время каждого обращения к БД и провайдеру.
- Async-обработчики и AsyncSession с psycopg. Поддерживает текущий драйвер PostgreSQL, SQLAlchemy-модели и миграции.
- Async-обработчики с заменой драйвера на asyncpg. Добавляет миграцию драйвера и другой набор параметров подключения. Измеренной потребности в этой замене сейчас нет.

## Решение и причины

Используем SQLAlchemy AsyncEngine и AsyncSession поверх async-режима psycopg. Порты хранения, сценарии с ожиданием и HTTP-обработчики асинхронны. Отдельная сессия принадлежит одной транзакции и одной задаче.

SMTP выполняется через aiosmtplib, SMS — через HTTPX AsyncClient. HTTPX уже использовался в тестах. Проверка сертификата, таймауты и повторная отправка сохраняются.

Argon2 выполняется через asyncio.to_thread, поскольку хеширование нагружает CPU. Операции файловой системы для снимков метрик также выносятся из event loop. Чистые доменные вычисления выполняются обычными функциями.

Alembic использует асинхронное подключение и адаптер SQLAlchemy run_sync для своего штатного синхронного API. Event loop и сетевое подключение остаются под управлением async-драйвера.

## Последствия

Вызов I/O-порта требует await. Транзакции оформляются через async with. Сессии не разделяются между конкурентными задачами. Фабрика сервисов и тестовые реализации портов тоже асинхронны. API закрывает принадлежащий ему engine при остановке, CLI — после прохода обслуживания.

Смена модели сама по себе не доказывает рост производительности. Ограничения пула подключений, время провайдера и стоимость Argon2 остаются предметом измерения.

## Условия пересмотра

Вернуться к выбору драйвера при измеренной несовместимости, существенных накладных расходах или появлении требуемых возможностей другого драйвера. Выносить CPU-работу в отдельные процессы при подтверждённом насыщении потоков и памяти. Для длительных фоновых операций пересмотреть границу между API и отдельным worker.
