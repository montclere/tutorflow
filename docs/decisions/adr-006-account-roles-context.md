# ADR-006 — единый аккаунт и независимые контексты кабинетов

- Дата — 2026-11-26.
- Статус — принято.
- Связи — UC-001, UC-002, UC-003, BR-075, BR-087, BR-089, BR-090.

## Контекст выбора

Один человек может преподавать, сам учиться и сопровождать другого ученика. Единственная роль аккаунта заставляла создавать несколько учётных записей. Владелец согласовал отдельное подключение ролей без автоматического создания всех кабинетов.

## Альтернативы

- Несколько аккаунтов с совпадающим контактом. Это усложняет пароль, восстановление, выход и однозначную идентичность человека.
- Один аккаунт с переключаемой ролью в сессии. Переключение кабинета в одной вкладке изменяло бы контекст другой.
- Один аккаунт с явно подключёнными ролями; сессия подтверждает личность, каждый маршрут выбирает и проверяет собственный контекст.

## Решение и причины

Выбран третий вариант. Роли хранятся отдельными уникальными назначениями аккаунта. Вход выбирает доступный кабинет без активации роли. Существующий пользователь включает teacher отдельным защищённым действием; student и adult подключаются вместе с принятием соответствующего приглашения. Совпадение контакта без входа не разрешает добавление роли.

Actor представляет проверенный контекст конкретного действия. Для принятия приглашения используется подтверждённая личность без требования заранее иметь целевую роль. Добавление роли, погашение приглашения и связь входят в общую транзакцию ADR-004. Изменения ролей одного аккаунта сериализуются блокировкой аккаунта.

## Последствия

Общий профиль и пароль принадлежат одному человеку. Роль ученика взрослого означает его собственную учёбу; аккаунт ребёнка остаётся отдельным. При отключении связи остальные роли сохраняются. Маршруты с неоднозначным контекстом разделяются; API выдаёт набор ролей вместо одной роли аккаунта. Существующий преподавательский интерфейс адаптируется к этому контракту без реализации новых экранов.

## Условия пересмотра

Разные правила профилей по ролям, отзыв ролей, отдельные пространства организаций или повышенные полномочия могут потребовать дополнительных процессов. Переключение глобальной роли в сессии не следует вводить без решения проблемы параллельных вкладок.
