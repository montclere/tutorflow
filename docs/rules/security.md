# security

Обязательные правила безопасности для будущего кода.

- Не клади секреты, реальные данные пользователей и резервные копии в Git, логи или тестовые фикстуры.
- Проверяй входные данные и права на сервере для каждого действия и объекта.
- Не доверяй роли, владельцу и стоимости операции из клиентского запроса.
- Не собирай персональные данные без продуктовой необходимости; опиши доступ, срок и удаление до реализации.
- Не возвращай внутренние исключения и конфигурацию клиенту.
- Проверяй отказы и доступ к чужому объекту тестами; внешние сервисы в unit-тестах заменяй фейками.
- Не выполняй удаление данных и операции на рабочем сервере без поручения, определяющего цель и объём.

## Проект первого API

- Проверять доступ по [ADR Students](../adr/students.md) и применять [ADR Privacy](../adr/privacy.md) к сбору, диагностике и хранению.
- Не использовать ссылку на новую карточку для выдачи существующей истории. Не писать секрет в URL API, ответы с ошибками или журналы.
- Не доверять X-Forwarded-For и аналогичным заголовкам вне настроенного списка доверенных reverse proxy; иначе rate limit по IP обходится клиентом.
- Проверять роль и связь внутри изменяющей транзакции, запрещать назначение при принятии, владельца и аккаунт из тела.
- Доступ родителя не удостоверяет родство, возраст или законное представительство.
