# Документация

- Цели продукта храни в `product.md`, пользовательские сценарии — отдельными файлами в `use-cases/`, точное поведение существующих модулей — в `modules/<модуль>/business-rules.md`, требования к будущим областям — в [planned-business-rules.md](planned-business-rules.md).
- Создавай папку модуля только при наличии соответствующего модуля backend. Продуктовая область сама по себе не задаёт архитектурную границу.
- Используй глобальные постоянные ID UC и BR. Перед добавлением найди свободный номер; уникальность проверяют общие утилиты. Название модуля хранится отдельно от ID, номер GitHub Issue — отдельно от обоих.
- Сохраняй ID UC и BR. Различай утверждённое правило и статус его реализации. Изменение правила согласуется отдельно от правки кода.
- Статус реализации, порядок задач и зависимости веди в GitHub Issues и Project. Назначение и параметры команд ищи в справке утилит. Формат и связи UC/BR проверяй режимом документов из [утилит](../scripts/).
- Существенный технический выбор фиксируй в `decisions/adr-NNN-краткое-имя.md` по [шаблону](templates/adr.md). ADR нужен при реальной альтернативе, когда причины выбора и условия пересмотра пригодятся на следующем этапе.
- Обычные соглашения, применение стандарта и общепринятые практики сами по себе не требуют ADR. Текст ограничивай контекстом выбора, альтернативами, причинами, принятыми ограничениями и условиями пересмотра.
- Принятый ADR сохраняет историческую причину. При изменении выбора добавляй новый ADR и связывай его с заменённым решением.

- Шаблоны и инструкции по заполнению храни в templates/. Предметные документы содержат требования, сценарии и принятые решения.
- Для новых BR и UC используй [шаблон правила](templates/business-rules.md) и [шаблон сценария](templates/use-case.md). Перенос сохраняет ID и смысл требований. Сквозной UC ссылается на BR из разных модулей.
- Используй текст, заголовки и списки. Выделения и декоративные элементы в предметных документах не нужны.

- При задаче открой выбранный UC и только связанные BR. Папки соседних модулей нужны по ссылкам и зависимости.
- Сценарии находятся в [use-cases](use-cases/), бизнес-правила — в [modules](modules/), шаблоны — в [templates](templates/), принятые решения — в decisions/.
