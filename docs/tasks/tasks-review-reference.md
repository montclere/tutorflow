# Задания и проверка по референсам

Исполнитель: текущий агент. Ревьюер: владелец проекта. Статус: готово к ревью.

Ветка: `style/tasks-review-reference`, отдельный worktree со снимком текущего `feat/main-reference`. Актуальный frontend ещё не интегрирован в `dev`; существующие правки сохранены как основа.

Источники: задания владельца, `TutorFlow_Tasks_Reference.png`, `TutorFlow_Review_Reference.png`. Правила: TASKS-UI-1, REVIEW-UI-1, TASKS-1…9, REVIEW-1…4. Область: представление заданий и проверки, локальные CSS и черновик ввода проверки в памяти. Общие файлы: `CabinetShell.tsx`, только изолированная тема учебных страниц в `layout.module.css`; только тексты этих разделов в `cabinet.ru.ts` и `tasks.ru.ts`; только новые именованные токены в `tokens.css`; `docs/adr/web.md`, `docs/stages.md`. Не менять модели заданий, библиотеку, банк, контракты, API, формы сохранения/выдачи и остальные разделы.

Критерии: две равные панели чата и черновика с независимой прокруткой и доступными нижними действиями; действующие подсказки, параметры, перестановка/замена/сохранение/PDF. Проверка: очередь и единая панель решения; компактная автопроверка, критерии, исходное решение, предложение ИИ отдельно от решения человека. Комментарий и балл сохраняются при навигации до перезагрузки; сохранение черновика не оценивает работу. Оценка и возврат используют прежние явные действия преподавателя. Демонстрационный ИИ, распознанный пример и отсутствие серверного API/оригиналов фото обозначены честно; фиктивные интеграции не добавляются.

## Результат и проверки

- Задания: две равные панели с независимым скроллом, светлые сообщения, постоянные четыре подсказки, прежние параметры и отправка Enter/Shift+Enter, отдельные заголовок и редактируемая тема черновика, исходные задачи и ответы, сводка из модели. На desktop все четыре нижние кнопки в один ряд и остаются на месте при прокрутке задач. На телефоне панели идут последовательно; настройки — целыми строками.
- Проверка: заголовок без поясняющего подзаголовка, прежняя очередь и вкладки, светлое выделение выбранной работы, единая правая панель с условием/критериями, исходным решением, кратким предложением ИИ и комментарием. «Подробности проверки» раскрывают полный разбор. Нажатие на зелёное предложение («Взять оценку ИИ») переносит балл и комментарий только в черновик. ИИ не меняет итоговый статус, публикация остаётся отдельной кнопкой преподавателя.
- Черновик проверки хранится в памяти до перезагрузки отдельно по выдаче, попытке и задаче. Сохранение не вызывает `gradeTask` и не меняет библиотеку. После явной оценки/возврата черновик очищается. Три новых unit-теста сначала падали на отсутствующем поведении, затем стали зелёными; проверены изоляция, стабильный снимок, подписки и отсутствие публикации при сохранении или результате ИИ.
- `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` — успешно: 299 тестов в 48 файлах. Демо-сборка также успешна. Сохраняется исходное предупреждение о JS-чанке больше 500 kB; новых зависимостей нет.
- Playwright / Google Chrome: 1648, 1440, 1280, 1180, 1024, 821, 820, 768, 430, 390, 375, 320 px — нет горизонтального переполнения страницы. На 1648 × 928 измерением подтверждены равные ширина и высота панелей сборки. При прокрутке черновика положение нижних кнопок не меняется; поле чата остаётся доступным.
- Проверены параметры и подсказки, перестановка и замена задачи, отмена изменения ИИ, сохранение задания и теста с появлением в библиотеке, переходы трёх вкладок, отмена/подтверждение очистки и disabled-состояние пустого черновика. PDF проверен до формирования исходного печатного листа и вызова `window.print`; системный диалог и файл PDF не создавались.
- Проверены критерии, запуск/ожидание ИИ, disabled-публикация до выбора преподавателя, явное применение предложения, сохранение комментария/балла при смене ученика и переходе в финансы/обратно, итоговая оценка 5 из 6, обязательный комментарий для возврата, успешный возврат и пустая вкладка тестов. Исправлена нестабильность доступного имени поля комментария при ошибке валидации. Ошибок JavaScript и загрузки ресурсов нет; reduced motion включён. Safari/WebKit не проверялся.
- 10 пар снимков до/после для лендинга, главной, расписания, учеников и финансов на 1600 и 390 px совпали побайтно. 160 исходных файлов моделей заданий, данных, расчётов, API, общих компонентов и лендинга сохранены по SHA-256; прочие файлы вне задачи также сверены перед переносом.
- `./scripts/dev.sh check` останавливается на прежних ссылках в `docs/tasks/landing-ux.md` и `docs/adr/web.md` на удалённый `UX-REVIEW.md`. Общая интеграционная проверка не завершена; чужое удаление сохранено.

## Границы демо и передача

Серверного API заданий/проверки и внешней ИИ-модели в проекте пока нет. Сохранение и оценка используют исходное хранилище демо в памяти; новых серверных обещаний нет. Исходные «фото» представлены именами файлов, два существующих текста решений — подготовленные демонстрационные примеры. Они не заменены генерированным OCR; оригиналы фото не создавались, отсутствие оригиналов указано в раскрытии вложений. Доступный URL вложения открывается отдельно; для имени без файла просмотр не имитируется. Очередь показывает реальные две ожидающие работы из модели, а не четыре строки из картинки.

Они используют исходные данные и реальные действия демо; PNG-референсы в интерфейс не встроены. Результат перенесён из worktree в основной каталог после проверки хешей.
