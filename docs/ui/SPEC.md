# Вёрстка: лендинг с регистрацией и кабинеты

**Этап: только интерфейс.** Лендинг, кабинеты репетитора и ученика как настоящее приложение: компоненты, маршруты, переходы. **Бизнес-логику не делаем:** никаких API, базы данных, авторизации, платежей, ИИ, отправки писем. Все данные — моки.

## 1. Маршруты

| Путь | Экран |
|---|---|
| `/` | Лендинг с регистрацией |
| `/teacher` | Репетитор → Обзор |
| `/teacher/schedule` | Расписание; вид и дата в адресе: `?view=day\|week\|month\|list&date=ГГГГ-ММ-ДД` |
| `/teacher/students` | Ученики; вкладка и карточка в адресе: `?status=active\|pause\|archive&student=id` |
| `/teacher/tasks` | Задания → «Создать с ИИ» |
| `/teacher/tasks/bank` | Задания → «Банк ЕГЭ и ОГЭ» |
| `/teacher/tasks/mine` | Задания → «Мои задания» |
| `/teacher/review` | Проверка |
| `/teacher/finance` | Финансы; месяц в адресе: `?month=ГГГГ-ММ` |
| `/student` | Ученик → Главная |
| `/student/tasks` | Задания |
| `/student/trainer` | Тренажёр |
| `/student/exam` | Вариант ЕГЭ |
| `/student/progress` | Прогресс |

Вкладки «Банк» и «Мои задания» — отдельные маршруты. Вкладки внутри ученических «Заданий» — локальное состояние.

## 2. Переходы между экранами

```
Лендинг /
 ├─ «Создать кабинет бесплатно» → прокрутка к форме регистрации
 ├─ Форма: шаг 1 → (почта → код) → шаг 2 → шаг 3 «Кабинет готов» → «Перейти в кабинет» → /teacher
 ├─ «Смотреть демо» → /teacher (временно, пока нет отдельного демо-адреса)
 ├─ «Войти» (шапка) → прокрутка к форме регистрации
 └─ «Я ученик или родитель» → подсказка + ссылка «Посмотреть кабинет ученика» → /student

Кабинет
 ├─ Логотип → /
 ├─ Переключатель «Репетитор / Ученик» → /teacher или /student
 ├─ Пункты меню → свои маршруты, активный пункт подсвечен
 └─ Ссылки внутри экранов → свои маршруты
```

## 3. Что работает, а что нет

**Работает (локальное состояние):** шаги регистрации и проверки полей; переключение ролей, меню, вкладки; чат ИИ с заготовленным ответом; очередь проверки; тренажёр; вариант ЕГЭ с таймером; переключатель «Сегодня / Завтра» в «Обзоре»; копирование свободных окон; мобильное меню.

**Не работает:** создание урока, ученика, оплаты, экспорт, PDF, отправка задания, импорт, уведомления, поиск. Все такие кнопки вызывают **одну** функцию `notifySoon(label)` и показывают уведомление «… — скоро будет».

## 4. «Обзор» репетитора (`/teacher`)

Ровно четыре элемента сверху вниз. Деньги и финансовые плитки с «Обзора» убраны: суммы живут только в «Финансах».

1. **Шапка.** «Добрый день, {имя}», под ним дата мелким серым. Справа «Задание» (вторичная кнопка) и «Урок» (основная), обе с иконкой «плюс». Другого текста нет.
2. **Ряд 1, около 60/40.**
   - **«Сегодня»:** переключатель «Сегодня · N / Завтра · N», ссылка «Расписание →». Строка урока: время, аватар с инициалами, имя, предмет, бейдж статуса («Проведён», «через 25 мин», «Оплачено», «Долг»), кнопка «Войти». Прошедшие уроки приглушены. Основной кнопкой выделен ближайший непройденный урок.
   - **«Требует внимания»:** счётчик в заголовке, до 5 строк, у каждой одна кнопка: «Отметьте урок» → «Проведён», «N работ на проверку» → «Проверить» (ведёт на `/teacher/review`), «Долг» → «Напомнить», «Пакет заканчивается» → «Продлить», «Не занимается N дней» → «Написать». «Проведён» убирает строку; когда строк нет — «Всё в порядке».
3. **Ряд 2, 50/50.**
   - **«Неделя»:** 7 столбиков Пн–Вс по числу уроков, сегодняшний выделен; в заголовке «N уроков · загрузка P%» (загрузка = уроки / ёмкость недели из моков). Под графиком — свободные окна и кнопка «Поделиться»: копирует окна текстом в буфер обмена. График нарисован простыми элементами, без библиотеки.
   - **«Подготовка к экзаменам»:** ссылка «Все →». Строка: аватар, «Имя · экзамен», «N дней · слабое место №X» или «не занимается N дней», полоса готовности, бейдж «61% ↑» (рост зелёный, падение красное). Если никто из учеников не готовится к экзамену — блок не показывается, «Неделя» занимает всю ширину.
4. На телефоне — одна колонка в том же порядке.

Данные приходят из `getTeacherOverview()`, тексты — из `content/cabinet.ru.ts`.

## 5. «Расписание» репетитора (`/teacher/schedule`)

Вид и дата хранятся в адресе: `?view=week&date=2026-11-17`. По умолчанию «Неделя», на телефоне (до 520 px) — «Список».

1. **Шапка.** Слева заголовок периода («16 — 20 ноября», «Ноябрь 2026», «Вторник, 17 ноября»; по нажатию открывается мини-календарь перехода к дате), стрелки назад / вперёд и кнопка «Сегодня». Справа переключатель вида «День / Неделя / Месяц / Список» и основная кнопка «Урок».
2. **Фильтры.** Выбор ученика с поиском по имени, тип урока (индивидуальный, групповой, пробный), предмет — только если у репетитора в профиле два предмета и больше. Справа сводка «N уроков · M свободных окон» за видимый период. Свободные окна считаются по всем урокам, фильтры их не меняют.
3. **Неделя.** Сетка по часам в рабочее время из моков (по умолчанию 12:00–20:00), семь колонок Пн–Вс. Высота блока урока равна его длительности; внутри имя ученика (полное — в подсказке), время и красная метка «долг», если есть долг. Пересекающиеся уроки делят ширину колонки. Прошедшие уроки приглушены, сегодняшняя колонка выделена, красная линия «сейчас» с точкой. Свободное окно (не короче заданного в моках минимума) — блок «свободно», виден при наведении и фокусе; по нажатию открывается быстрое создание урока (ученик, длительность, повтор; сохранение — `notifySoon`). На телефоне сетка прокручивается по горизонтали внутри контейнера.
4. **День.** Переключатель «Сегодня / Завтра», слева уроки дня с цветной полосой, справа панель ближайшего урока: прошлая тема, домашнее задание, баланс, заметка, «Войти» и «Перенести».
5. **Месяц.** Сетка Пн–Вс: цветные точки уроков и подпись «N уроков», сегодня выделено, выходные темнее. Нажатие на день открывает «День» на эту дату.
6. **Список.** Уроки на ближайшие две недели по дням, с подзаголовками дат.
7. **Карточка урока.** По нажатию на урок в любом виде открывается панель с данными урока и кнопками «Войти», «Перенести», «Отменить», «Проведён» (все через `notifySoon`).
8. **Цвета.** У ученика один цвет (поле `color` в моке, палитра — токены `--cab-tone-*`); он же у аватара во всём кабинете. Переключателя цвета нет.
9. **Расчёты** — чистые функции с тестами: `model/scheduleLayout.ts` (позиция блока по времени, колонки при пересечении, свободные окна, линия «сейчас»), `model/dates.ts`, `model/scheduleRange.ts`, `model/lessons.ts`.

Демо-данные: репетитор Анна ведёт только математику (ЕГЭ профиль, ЕГЭ база, ОГЭ, алгебра 10 класса). «Обзор» берёт уроки дня, недели и свободные окна из тех же моков расписания.

## 6. «Ученики» репетитора (`/teacher/students`)

Репетитор ведёт один предмет, поэтому поля «Предмет» у ученика нет нигде. Вместо него — «цель»: «ЕГЭ профиль · цель 80+», «ОГЭ · цель 5», «Алгебра · 10 класс».

**Модель ученика** (`mocks/types.ts`): имя, инициалы, цвет, цель, статус (`active` / `pause` / `archive`), расписание (раз в неделю, дни, время, длительность), оплата (поурочно или абонемент), баланс в копейках (плюс — предоплата, минус — долг), ближайший урок, число проведённых уроков, дата начала, подключён ли Telegram, родитель, источник, подготовка к экзамену (дней до экзамена, готовность, слабые номера), последние уроки с домашним заданием, заметка. Расписание и ближайший урок не хранятся в моках: слой `data` считает их из шаблонов уроков и расписания, поэтому список, «Расписание» и «Обзор» не расходятся. Цвет ученика один на весь кабинет: аватар, блоки расписания, «Обзор».

**Список.**
1. Шапка: «Ученики» и «Пригласить» (основная). Учеников добавляют только через приглашение, импорта нет.
2. Вкладки «Активные · N / Пауза · N / Архив · N» (адрес `?status=`), поиск по имени, кнопка «Должники» (только с отрицательным балансом).
3. Таблица из пяти колонок и стрелкой «открыть»: ученик (аватар, имя, цель), занятия («2 раза в неделю» и дни), тариф («Поурочно · 1 500 ₽ за урок» или «Абонемент · 8 × 1 250 ₽ · осталось 1»), «Долг / предоплата» (плашка словами: красная «Долг 1 200 ₽», зелёная «Предоплата 4 500 ₽», серая «Нет долга»), следующий урок («Сегодня 15:00» синим, «Чт 16:00»). Размер текста — 16 / 14 px, у шапки серая подложка.
4. Вся строка кликабельна (мышь и Enter), выбранная строка подсвечена. Длинные строки обрезаются с полным текстом в подсказке.
5. Пустые состояния: нет учеников — «Пригласите первого ученика» с кнопкой; поиск ничего не нашёл — «Никого не нашли»; пустые «Пауза» и «Архив» и фильтр «Должники» имеют свои подписи.
6. На телефоне (до 520 px) таблица превращается в карточки: аватар, имя, цель, долг или предоплата словами, следующий урок.

Слова «баланс» в интерфейсе нет: он непонятен. Значение (плюс — предоплата, минус — долг) всегда подписано словом.

**Карточка ученика** — панель справа шириной около 640 px, на телефоне на весь экран. Закрывается крестиком, кликом по фону и Esc; фокус возвращается на строку. Открытая карточка в адресе: `?student=id`.
- Шапка: аватар, имя, «цель · с 1 сентября».
- Кнопки «Урок» (основная), «Оплата», «Задание», «Ещё» (пауза, в архив, удалить) — все через `notifySoon`.
- Четыре плитки (2 × 2): долг / предоплата, следующий урок, тариф (поурочно или абонемент с остатком), уроков проведено.
- Вкладки: «Обзор» (расписание; последние уроки с бейджем «ДЗ 9/10» или красным «ДЗ не сдано»; контакты: Telegram, родитель, источник; заметка; блока подготовки к экзамену нет), «Уроки», «Оплаты», «Задания», «Заметки».
- **Вкладка «Задания».** Сверху три плитки: средний результат (по числу задач, не по числу работ), всего ошибок, тема, где ученик ошибается чаще всего. Ниже раскрывающиеся задания: название, «Выдано · Сдано · время», бейдж результата («9 из 10», зелёный от 80%, красный до 50%) или статус. Внутри: у проверенной работы список ошибок (номер, тема, «Ответ ученика» красным, «Верно» зелёным) или «Без ошибок»; у сданной — «Ждёт вашей проверки» и кнопка «Проверить» (на `/teacher/review`); у невыданной — «Ученик ещё не приступал». Первое задание с ошибками раскрыто сразу. Ниже блок «Тренажёр». Расчёты — `model/studentTasks.ts`, число ошибок в моках совпадает с результатом (тест).

Форматирование денег, «N раз в неделю» и склонения («1 урок / 3 урока / 5 уроков») — в `model/format.ts` и `model/plural.ts`, с тестами. Логика списка (фильтры, счётчики, статус оплаты, расписание из шаблонов, подпись ближайшего урока) — в `model/students.ts`.

## 7. «Финансы» репетитора (`/teacher/finance`)

Упрощённый вид: четыре блока сверху вниз, больше ничего. Графика по месяцам, дохода по ученикам, цели месяца и скрытия сумм нет.

1. **Шапка.** Слева выбранный месяц («Ноябрь 2026») и стрелки «назад / вперёд» (месяц в адресе `?month=2026-11`, листать можно в пределах истории). Справа меню «…» с пунктом «Экспорт в Excel» и основная кнопка «+ Оплата» (обе через `notifySoon`).
2. **Ряд 60/40** (от 1181 px, уже — один столбик).
   - Слева синяя карточка «Пришло денег за ноябрь»: крупная сумма белым, лаймовый чип «+12% к октябрю» (при падении — белый полупрозрачный чип, красного здесь нет), внизу мелко «42 оплаты · 54 урока проведено».
   - Справа три карточки столбиком: «Ожидается до конца месяца», «Должны сейчас» (сумма красным, «1 ученик», красная рамка только при ненулевом долге), «Предоплаты» («8 уроков вперёд»).
3. **«Долги и абонементы».** Строки: аватар, имя, подпись. Должник: «долг 1 200 ₽ · 3 дня · платит папа» (кто платит, берётся из родителя ученика; без родителя части нет), красным. Абонемент на исходе: «абонемент: остался 1 урок». У каждой строки одна кнопка («Напомнить» или «Продлить»); абонементы «в норме» не показываются. В заголовке лаймовая «Напомнить всем». После нажатия кнопка становится «Отправлено» (только состояние интерфейса). Если пусто — «Долгов нет».
4. **«Операции».** Фильтр «Все / Оплаты / Уроки» (ToggleGroup; корректировки видны во «Всех») и поиск по ученику. Колонки: «Дата», «Ученик», «Операция», «Способ» (СБП, наличные, перевод, «—»), «Сумма» (вправо; поступления зелёным, списания обычным цветом). Показаны все операции месяца, без «Показать ещё». На телефоне (до 520 px) — список карточек. Пустые состояния: «В этом месяце операций нет» и «Ничего не нашли».

**Как считается.** «Пришло» и число оплат — из истории месяцев в моках. «+12%» — рост к прошлому месяцу. «Ожидается» — цена урока × ещё не прошедшие уроки месяца только у поурочных учеников плюс текущие долги; уроки из абонементов не считаются (они уже оплачены), долги добавляются только к текущему месяцу. «Должны» и «Предоплаты» — из балансов активных учеников на сегодня.

Расчёты (рост, «ожидается», уроки по предоплате, фильтр операций, сдвиг месяца) — чистые функции в `model/finance.ts` с тестами; суммы форматирует `formatRubles`, все суммы в копейках из `mocks/finance.ts`.

## 8. Архитектура и дизайн

- **Стек:** Vite + React + TypeScript, CSS Modules и CSS-переменные; в кабинете — компоненты shadcn/ui (Tailwind v4 только слоями `theme` и `utilities`, без сброса стилей, чтобы не трогать лендинг) и иконки `lucide-react`.
- **Токены:** единственный набор цветов, радиусов и шрифтов — `src/styles/tokens.css`. Тема shadcn в `src/styles/tailwind.css` состоит из алиасов на эти токены, своей палитры нет.
- **Визуальный язык:** лендинг яркий (синий фон, огромные заголовки, лайм), кабинет светлый и спокойный. Шрифты Unbounded (заголовки, крупные цифры) и Manrope (текст).
- **Иконки:** только `lucide-react`, один стиль, толщина и размер. Эмодзи в интерфейсе не используются.
- **Каркас кабинета:** боковое меню (из конфига для каждой роли), шапка, область контента.
- **Моки** — `src/cabinet/mocks`, слой `src/cabinet/data/*` возвращает моки; позже его заменят на API.
- **Тексты** — `content/landing.ru.ts`, `cabinet/content/cabinet.ru.ts`. Название, цена, пробный период — в `siteConfig`.
- **Детали:** единая шкала отступов (`--space-*`), одинаковые радиусы и высоты кнопок, `tabular-nums` у чисел, состояния hover / focus / active у всего кликабельного, переходы 150–200 мс, отключённые при `prefers-reduced-motion`, контраст не ниже WCAG AA.

## 9. Адаптив и доступность

- Брейкпоинты: лендинг 1100 / 860 / 560 px, кабинет 1180 / 820 / 520 px. На телефоне меню кабинета выезжает по кнопке.
- Один `h1` на страницу, `nav`, `main`, `section` с заголовками; вкладки — `role="tablist"`; переключатели и чипы — `aria-pressed`.
- Всё доступно с клавиатуры, фокус виден.

## 10. Не делать

API и серверные обработчики, базу данных, авторизацию и сессии, сохранение в `localStorage`, ИИ-вызовы, генерацию PDF, отправку писем и сообщений, платежи, тёмную тему.

## 11. Критерии готовности

- [ ] Путь «лендинг → регистрация → «Перейти в кабинет» → /teacher» работает, как и «Смотреть демо».
