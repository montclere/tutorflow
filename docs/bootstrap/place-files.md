# Куда раскладывать файлы

1. Распакуй ZIP **в корень нового приватного репозитория** с сохранением скрытых `.agents/` и `.github/`.
2. `docs/product.md`, `docs/use-cases.md`, `docs/business-rules.md` — единственные продуктовые MD (черновики UC/BR требуют отдельной ревизии на точность формулировок, не заявляй что все 75 готовы к коду).
3. `AGENTS.md` — постоянная короткая инструкция Codex.
4. `.agents/skills/*/SKILL.md` — три процедурных скилла, загружаются только в соответствующих задачах.
5. `scripts/check.py` — точечные и CI проверки; `scripts/checks.json` — конфигурация выбранного стека; `backend/tests/rule-map.json` — карта BR → тесты.
6. `.github/workflows/ci.yml` — рабочая спецификация CI-процесса; до выбора стека проверяет только консистентность спецификации. **После появления исходного кода сценарий fail-closed, пока не подключены настоящие тесты.**
7. `.pre-commit-config.yaml` — быстрые локальные проверки pre-commit.
8. `docs/bootstrap/setup-codex.md` — одноразовый полный промпт настройки, **не постоянный документ репозитория**: передай Codex и затем при желании удали.
9. `docs/bootstrap/run-issues.md` — готовые короткие промпты операций, тоже можно хранить только у себя.
10. Полное содержимое файлов включено в ZIP.

Порядок: распаковать → передать Codex `docs/bootstrap/setup-codex.md` → утвердить стек → запустить настройку → сгенерировать первую очередь Issues → начать реализацию.
