# new-module

Когда: новая фича или модуль backend. Пути внутри процедуры — от корня репозитория.

1. Прочитай `backend/AGENTS.md`; выбери простой модуль или слои по реальной сложности.
2. Запиши правила в behavior и согласуй контракт в frontend-api со вторым участником.
3. Напиши тест на бизнес-правило, затем минимальную реализацию по процедуре tdd.
4. Отдели БД и внешние сервисы от логики; не создавай пустые слои.
5. Добавь миграцию при изменении схемы, обработку ошибок и проверку прав на каждом объекте.
6. Проверь через API успех, неверный ввод, отсутствие доступа и чужой объект.
7. Подключи проверки модуля к `./scripts/dev.sh check`; обнови decisions, задачу и stages.

Стек и эталонные модули ещё не выбраны; не ссылайся на внутренние модули форума.
