# tdd

Когда: новая логика или исправление бага.

1. Возьми правило по ID из behavior; новое правило запиши до теста. Для бага опиши воспроизводимый результат.
2. Напиши тест на наблюдаемое поведение: успех, границы и применимые отказы.
3. Убедись, что тест падает из-за отсутствия поведения, а не ошибки окружения.
4. Реализуй минимальный код, добейся зелёного теста, затем рефактори.
5. Правила тестируй без сети; HTTP-контракт, права и БД — на границе интеграции.
6. Для критичных прав и безопасности проверь, что удаление защиты ломает тест; восстанови код и повтори проверку.
7. Запусти проверки модуля и общую команду; сообщи реальные результаты.

- Не проверяй только успешный статус или вызов мока вместо результата.
- Не пересчитывай ожидаемый результат тем же алгоритмом, который проверяешь.
- Для документации и простых заглушек достаточно проверки структуры и ссылок.
