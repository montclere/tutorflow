# UC-006 — Преподаватель задаёт регулярное расписание

- Актор: преподаватель.
- Цель: назначить серию занятий и управлять исключениями.
- Основной поток: 1) превращает урок в повторяющийся или настраивает несколько дней; 2) выбирает бессрочное/до даты/по числу повторений; 3) при необходимости ставит паузу, каникулы или исключения.
- Варианты: изменение одного события, будущих событий или серии; редактирование участников конкретного группового урока; временные исключения и отсутствие преподавателя.
- Результат: повторяемый план, отдельные занятия допускают индивидуальные изменения.
- Требования: BR-037–BR-043.
- Гипотеза ценности: гибкие регулярные занятия без ручного пересоздания.
- Статус: С — API, повторение и неизменяемость прошедших событий согласованы; технические решения принимаются по указанным ограничениям.

## Согласованные границы API

Поддерживаются ежедневные, еженедельные и ежемесячные повторения с интервалом; для недельного расписания выбираются дни недели. Серия заканчивается по дате включительно, по числу плановых повторений либо остаётся бессрочной. Каникулярный пропуск не сдвигает следующие даты и не создаёт компенсационное занятие.

Конкретное занятие имеет точное время в UTC. Для серии дополнительно сохраняются локальное время и часовой пояс планирования: повторение не выводится простым прибавлением одинакового числа секунд. Изменение часового пояса профиля не меняет серию. Поведение календарных исключений сверяется с RFC 5545 и фиксируется в ADR при реализации.

Редактируются отдельное занятие, выбранное и последующие либо вся будущая часть серии. Прошедшие и начавшиеся события остаются историей. Разница последних двух режимов — начало диапазона: выбранное будущее событие или ближайшее ещё не начавшееся событие.

По умолчанию индивидуальные исключения сохраняются, API сообщает о них. Преподаватель может явно выбрать их перезапись в изменяемом будущем диапазоне. Изменение отдельного урока не меняет серию неявно. Состав группы и цены обновляются для серии только явным действием; новая карточка в группе сама по себе не переписывает подготовленные занятия.

Паузы и каникулы исключают заданный период; возобновление возвращает прежние дни без компенсационного переноса. Для уже подтверждённых будущих событий операция сначала сообщает последствия и требует явного решения; скрытая отмена не выполняется. История сохраняется.

Расписание согласуется целиком; отказ от конкретной даты возможен отдельно. Изменение времени будущей части требует нового согласования затронутых событий. Остальные индивидуальные ответы не переносятся на изменённое время молча.

Бессрочность относится к правилу повторения, а не к бесконечной HTTP-выборке. API принимает ограниченный диапазон, использует пагинацию и настраиваемые технические пределы; конечная дата серии не навязывается. Горизонт подготовки событий и защитные ограничения не становятся произвольным продуктовым запретом числа уроков.

Преподаватель может исправлять будущие события с историей изменений. Запросы участников на перенос, финансовые последствия отмен и отметка проведения остаются UC-007–UC-008. Предыдущие независимые занятия сохраняются при изменении или удалении правила серии.

## Контракт завершённости

Повторение поддерживает daily, weekly и monthly с положительным интервалом. В недельном правиле каждому выбранному дню соответствует своё время и длительность; в одном дне одно повторение. Дневное и месячное правила используют время начала и длительность шаблона. Месячное правило сохраняет число месяца: отсутствующее число пропускается, а не переносится на последний день.

Локальное начало и IANA-зона задаются явно. Неоднозначное время требует выбора первого либо второго вхождения; несуществующее время возвращается как конфликт с возможностью явно пропустить его. Пропущенная несуществующая дата не считается повторением; каникулы применяются после отсчёта плановых повторений. API сообщает конфликты отдельно и не сдвигает время молча.

Серия создаётся из команды занятия либо существующего будущего занятия с проверкой версии; существующее занятие становится первым экземпляром без дубликата. Условия и участники сохраняются снимком. Изменение источников влияет только на явное обновление будущего шаблона.

Каждое подготовленное повторение связано с версией правила и исходной календарной датой. Перенос или удаление одного занятия сохраняет эту связь. Массовое изменение возвращает затронутые подтверждения и индивидуальные исключения; по умолчанию исключения сохраняются, явная перезапись разрешена только для будущих событий. Сохранённое исключение занимает свою исходную дату, поэтому новое правило не добавляет второй урок на эту дату.

Пауза бывает ограниченным периодом либо продолжается до возобновления. Прошедшая часть паузы остаётся в истории. Операции с подтверждёнными событиями требуют явного согласия на последствия, проверяют версию и выполняются атомарно. Удаление серии прекращает будущие повторения, сохраняя прошедшие занятия и историю.

Согласование серии действует для текущего будущего расписания; отдельный ответ на дату имеет приоритет. Проверяется действующий ответственный карточки, кабинет и CSRF. Смена будущего времени создаёт новое согласование. Без подключённого аккаунта согласование не имитируется.

Бессрочное правило не ограничивается датой технического горизонта. Подготовка и запросы выполняются в ограниченном диапазоне; повторные и конкурентные вызовы не создают дублей. Технические бюджеты, горизонт и размер страницы задаются настройками. Незавершённая подготовка не выдаётся за полный календарь.

До PR проверяются все BR-037–BR-043, миграции с существующими данными, права, гонки, откаты, сохранение истории и действующие API UC-005.
