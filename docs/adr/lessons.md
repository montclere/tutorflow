# ADR — Занятия и расписание

## Границы первой версии

Репетитор планирует индивидуальное занятие по своей карточке, ведёт недельное расписание и отмечает результат. Один урок имеет один временной интервал. Готовые кабинеты показывают расписание в пределах действующего доступа. Эти правила описывают первую локальную реализацию. Независимое ревью проводится перед интеграцией.

В первую версию входят разовые занятия и еженедельные серии с созданием записи урока по мере необходимости. Родитель с действующим разрешением видит расписание, историю занятий и отметки посещения. Владелец также выбрал единую запись для трёх ролей, подтверждение только при переносе, запрос переноса с обеих сторон, историю завершённых занятий и отдельное полное удаление. Обычные уведомления появляются в кабинете. Начисления, ДЗ, внешние каналы уведомлений, интеграции календарей, группы, рабочие часы и самостоятельная запись относятся к отдельным задачам.

## Сущность и полномочия

| ID | Правило |
| --- | --- |
| LES-1 | Занятие принадлежит одному преподавателю и одной его активной карточке. UUID занятия выдаёт сервер. Для создания преподаватель выбирает уже подключённый профиль ученика из своего кабинета. Сервер хранит ID активной карточки, к которой привязан профиль. Без такого ученика в списке создание недоступно. После создания карточка и владелец занятия неизменяемы. |
| LES-2 | Актора определяет серверная сессия. Только преподаватель-владелец создаёт занятие, меняет его содержание и итог. Изменение времени проходит через предложение и решение второй стороны по LES-33…36. Права для активной карточки проверяются через ACL-9/10 для каждой команды и чтения. Недоступный и отсутствующий объект дают одинаковый 404. Прямой запрос по ID и списки применяют одинаковые ограничения. |
| LES-3 | Преподаватель видит свои текущие занятия и историю, включая занятия по своим архивным карточкам. Привязанный ученик и родитель с действующим разрешением видят расписание своей активной карточки, включая прошедшие и отменённые занятия, а также отметки «проведено» и «пропуск». Родитель получает видимость через разрешение к той же карточке. Для назначения урока родительский аккаунт необязателен. Ученик и родитель видят текущую запись без истории правок, учительского аудита, закрытой заметки и состава серии. |
| LES-4 | Архивирование карточки отклоняется, пока у неё есть занятие или дата серии в состоянии `scheduled`, включая прошедшее без отметки. Преподаватель сначала отменяет занятие или отмечает результат. Проверка архива и запись занятия синхронизируются по блокировке карточки ACL-10. В архиве преподаватель читает историю. Обычные изменения требуют восстановления карточки. Явное удаление своей записи допускается и из архива по LES-37. Восстановление не возобновляет родительский доступ по STU-9. |
| LES-5 | В общем расписании ученика или родителя объединяются только доступные карточки. Запись идентифицируется по существующему ID карточки, без контактов и скрытых полей. Имя для подписей берётся из разрешённого представления карточки или кабинета. Конфликт, фильтр и пагинация не раскрывают чужие записи. |

## Время и конфликты

| ID | Правило |
| --- | --- |
| LES-6 | API принимает UTC с точностью до минуты для начала и целое число минут для длительности. Окончание вычисляет сервер. Настройки первой версии 15–240 минут включительно и горизонт 365 суток. Создание и перенос требуют `now < starts_at ≤ now + horizon` по времени сервера. Текущий момент вычисляется после получения блокировки для команды. |
| LES-7 | Часовой пояс профиля задаёт отображение и ввод. До отправки календарь преобразует локальные время и дату в UTC. Несуществующее локальное время при переводе часов отклоняется. При двусмысленном времени пользователь явно выбирает одно из двух смещений. Уже сохранённые моменты не сдвигаются при изменении часового пояса профиля. Границы недели вычисляются по началу двух соседних локальных понедельников. Если локальная полночь пропущена, используется первый существующий момент этой даты, а при двусмысленности — более ранний момент. Окно передаётся в UTC. |
| LES-8 | У преподавателя одновременно может быть только одно запланированное занятие, даже по разным карточкам. Запланированные даты серии занимают время с момента сохранения плана, даже если запись урока ещё не создана. Интервалы полуоткрытые `[starts_at, ends_at)`, поэтому занятия 09:00–10:00 и 10:00–11:00 совместимы. При переносе текущая запись исключается из сравнения. Отмена освобождает интервал. Календарь преподавателя не проверяет личное расписание ученика у других репетиторов. |
| LES-9 | Выбор интервала и запись атомарны. Для одного преподавателя конкурирующие создания, переносы и отмены сериализуются внутри БД. Защита от гонки учитывает даты серий и созданные уроки в одном расписании. План и запись, относящиеся к одной позиции, занимают один интервал. Отклонённый перенос сохраняет прежнее время. Ответ о конфликте не содержит ID или деталей другой записи. |
| LES-10 | Календарь возвращает созданные уроки и даты из плана серии, чьи интервалы пересекают запрошенное окно, включая занятие через полночь. Сортировка по началу и UUID занятия. В истории отменённое занятие сохраняет последнее запланированное время. Перенесённое занятие отображается на новом времени. Прошедшее занятие без результата остаётся `scheduled`. Интерфейс выводит «Нужна отметка» после окончания. Эта метка вычисляется при отображении по времени окончания. |

## Жизненный цикл

| ID | Исходное состояние | Действие и условие | Результат |
| --- | --- | --- | --- |
| LES-11 | Нет занятия | Владелец выбирает карточку, начало и длительность. Время свободно. | `scheduled`, версия 1 |
| LES-12 | `scheduled` | Вторая сторона принимает предложение по LES-36 до исходного начала. Новое начало в будущем, новый интервал свободен. | `scheduled`, тот же ID, новая версия при изменении интервала |
| LES-13 | `scheduled` | Владелец отменяет. Отмена допустима и после начала, если итог ещё не отмечен. Сохраняется серверное время записи, ввод задним числом отсутствует. | `cancelled`, интервал освобождён, возврат или повторное бронирование по LES-41 |
| LES-14 | `scheduled` | Владелец отмечает «проведено» либо «пропуск» с момента окончания. Решение преподавателя фиксируется явно. | `completed` либо `no_show`, новая версия |
| LES-15 | `completed`, `no_show` | Владелец исправляет ошибочную отметку на противоположную. | Новая отметка и версия, время занятия прежнее, событие исправления в истории |
| LES-16 | Любое | Запрос изменения передаёт актуальную `expected_version`. Применение той же отметки к актуальной версии является чтением результата без новой записи. Предложение переноса с прежним интервалом отклоняется, поскольку расписание не изменится. Запрос с устаревшей версией возвращает 409 даже при совпадении результата. Повтор отмены с актуальной версией возвращает текущую запись. Возврат из истории описан в LES-41/42. Удаление регулируется LES-37. | При конфликте состояние и история сохраняются |

LES-17 **[готово]** Для создания клиент формирует UUID попытки, один на подтверждение формы, и сохраняет его на случай повтора того же запроса. Уникальность проверяется для преподавателя. При доступной для изменения карточке тот же нормализованный запрос возвращает текущее занятие с 200, в том числе после первоначального времени начала. Повтор сравнивается с исходными параметрами, из которых создано занятие. Изменённый запрос с тем же UUID даёт 409. Ключ и исходные параметры хранятся с занятием. Ошибка команды не резервирует ключ. Сервер проверяет доступ к запрошенной карточке и карточке результата до выдачи результата или конфликта ключа.

LES-18 **[готово]** Встроенная история записи фиксирует создание, перенос с прежним и новым интервалом, отмену, отметку и исправление. Событие включает ID занятия, актора, время и версию. Запись истории входит в ту же транзакцию. История изменений предназначена преподавателю, служебные журналы используют код события и ID запроса по правилам приватности. История также фиксирует правки содержания и исход запроса переноса. События правки содержания хранят только имена изменённых полей. Причина действующей отмены или пропуска доступна участникам по LES-47. Контакты и данные для подключения к сторонним платформам в первой версии не собираются. Удаление регулируется LES-37. До публичного запуска оператор утверждает срок хранения расписания и истории правок, их экспорт и порядок физического удаления. [ADR приватности](privacy.md)

## Почему так

- **Один реальный урок на запись.** Это позволяет назначить ДЗ или начисление по устойчивому ID. Перенос меняет интервал, отмена остаётся в истории. Итог отмечает преподаватель.
- **Конфликт на уровне преподавателя.** Создание и перенос по разным карточкам сериализуются транзакционной блокировкой PostgreSQL по преподавателю. Порядок при записи — строка карточки, затем блокировка преподавателя. Подготовка ближайших уроков использует тот же порядок. Репозиторий хранит календарь карточки в одном документе и индексирует входные ID занятий, серий, запросов и предупреждений отдельными ссылками. Версии и проверка интервалов обрабатываются в одной транзакции.
- **Активные и архивные карточки.** ACL-9/10 покрывает активные карточки. Для истории своей архивной карточки потребуется узкая проверка владельца через Students. Архив требует разобрать открытые занятия, чтобы будущая бронь не осталась в расписании скрытно. Проверка архива передаётся через внутренний контракт модулей.
- **Доставка и деньги.** Сохраняются отличимые исходы и исправления. Автоматические последствия этих действий проектируются в своих модулях после утверждения правил оплаты или публикации.
- **Эксплуатация.** Модуль в текущем backend и PostgreSQL. Подготовку ближайших и уже наступивших уроков выполняет существующий процесс maintenance по LES-51. Календарь продолжает показывать даты из плана между запусками. Миграция добавляет таблицы. Существующие карточки начинают с пустым расписанием. План отката должен сохранять новые записи и согласованность запрета архива с открытыми уроками.

## Еженедельные серии

| ID | Правило |
| --- | --- |
| LES-19 | Серия принадлежит одному преподавателю и относится к одной карточке. В форме задаются первое локальное начало, часовой пояс IANA, длительность и конечное число занятий. Диапазон первой версии — 2–26 занятий. Повтор идёт каждые семь календарных дней по локальной дате и в тот же локальный час. Горизонт LES-6 применяется к каждому старту. У серии один ID, часовой пояс и версия, у каждого занятия свой ID, версия и неизменяемый порядковый номер в серии. |
| LES-20 | Сервер рассчитывает все интервалы. Серия сохраняет свой часовой пояс при изменении профиля. Для локального времени, которое встречается дважды, преподаватель выбирает первое или второе вхождение. Несуществующее локальное время останавливает команду с указанием даты из её плана. Просмотр плана показывает фактические даты и смещения, текущие конфликты и сохраняемые исключения. При пропущенном времени преподаватель может выбрать другой час либо разделить серию до и после проблемной даты. Сохранение пересчитывает план и повторно проверяет доступ, версии и интервалы в транзакции. |
| LES-21 | Один конфликт, неверная дата или выход за горизонт отклоняет всю серию. Связывающий ключ попытки работает по LES-17 на создание серии. Пространство ключей для создания серии и разового занятия раздельно. История фиксирует назначение серии. Полная запись ближайшего занятия создаётся по LES-51. |
| LES-22 | Действие «Только это занятие» применяет изменение к выбранной позиции. Если записи урока ещё нет, она создаётся по LES-50. Перенос помечает её ручным исключением. Отменённые занятия сохраняются по LES-13. Перенос и отмена одного занятия не меняют даты остальных. Версия серии увеличивается один раз при любой фактической команде над одним её занятием, включая отметку результата или исправление. |
| LES-23 | «Это и следующие» для переноса начинается с выбранного будущего занятия в состоянии `scheduled` без ручного исключения. План включает выбранное и последующие по порядковому номеру в серии будущие занятия в `scheduled` без ручных исключений. Для каждого включённого занятия новое локальное время равно новому началу выбранного плюс семь дней за каждый шаг по порядковому номеру, включая пропущенные исключения. Длительность для включённых занятий общая. Прошедшее, начатое, отменённое и вручную перенесённое сохраняется. Сохранение предложения фиксирует план изменений по позициям без создания уроков на каждую дату. Изменить число занятий или часовой пояс этой командой нельзя. |
| LES-24 | «Отменить это и следующие» начинает с выбранного будущего `scheduled` занятия, в том числе ручного исключения. По порядковому номеру отменяются все последующие будущие `scheduled`, включая ручные исключения. Отмена всех будущих дат описана в LES-55. Уже начатые, прошедшие и конечные записи сохраняются. Перед подтверждением календарь показывает состав отмены. |
| LES-25 | Перенос и отмена серии требуют текущую версию серии. Команды изменяют календарный план и историю атомарно и увеличивают версию серии один раз при фактических изменениях. Согласованный перенос или отмена сохраняют отдельные записи затронутых уроков для истории. Предложение сохраняет состав и рассчитанные интервалы. При согласии ученика перенос учитывает конфликты между рассчитанными интервалами, с оставленными исключениями и другими занятиями. При сравнении прежние интервалы переносимых записей исключаются. Ответ о конфликте указывает только конфликтующий интервал из плана запроса. Серийное повторение с устаревшей версией даёт 409. План без фактических изменений отклоняется. |
| LES-26 | Положение занятия в серии определяется порядковым номером, даже если вручную перенесённый урок теперь отображается в другом месте календаря. Порядок учитывается при выборе области действий, даты определяют, какие записи ещё можно менять. Продолжение после последнего занятия создаётся новой серией вручную. |

### Пример переноса

Серия на четыре понедельника идёт в 17:00. Второе занятие перенесено вручную на среду. Репетитор выбирает первое и предлагает перенос «Это и следующие» на 18:00. После согласия ученика первое, третье и четвёртое сдвигаются на 18:00, второе остаётся в среду. Если новое время четвёртого занято, не передвигается ни одно. Отмена «Это и следующие» от первого включает второе, если оно ещё впереди.

## Поведение кабинетов

| ID | Правило |
| --- | --- |
| LES-27 | Каждый кабинет открывает текущую неделю в зоне профиля, показывает её границы и выбранную зону. Доступны предыдущая и следующая неделя, переход к текущей и фильтр по карточке. Пустая неделя, загрузка и ошибка различаются. Отмена, пропуск и отсутствие отметки подписываются текстом. |
| LES-28 | Репетитор начинает создание из карточки или календаря. В календаре выбирает ученика из списка уже подключённых профилей. Приглашения и поиск по всем аккаунтам в форме занятия отсутствуют. Еженедельную серию создают из той же формы переключателем «Повторять». Зона профиля предлагается по умолчанию, выбранная зона и рассчитанные даты видны до подтверждения. Перед отменой интерфейс показывает занятие и область действия. При конфликте сохраняются поля формы. |
| LES-29 | Команды учителя показываются в зависимости от состояния записи и роли. После истечения допустимого времени или изменения версии сервер остаётся источником решения. Родитель и ученик открывают расписание и историю на отдельных неделях. Доступные действия выдаются по правилам переноса. |

## Карточка урока и общий доступ

| ID | Правило |
| --- | --- |
| LES-30 | Преподаватель, ученик и родитель работают с одним `lesson_id`. Учитель заполняет название, необязательные описание, инструкцию по подготовке и закрытую заметку. Название, описание и подготовка видны всем участникам. Заметка, версия серии и служебная история правок видны владельцу. Предлагаемые пределы для названия 1–120, описания до 1500, подготовки до 500 и заметки до 1500 символов. Поля — простой текст. |
| LES-31 | Описание и подготовка хранятся с занятием. Серия задаёт общий шаблон содержания. Как отдельный урок использует шаблон и как его править, описано в LES-53/54. Перенос серии меняет интервалы и длительность, сохраняя содержание. Переиспользуемый материал, файл или ДЗ получат отдельную сущность и связь с `lesson_id`, когда появится библиотека или сдача работ. |
| LES-32 | Назначение урока не требует приглашения. Уже подключённые ученик и родитель получают доступ к тому же уроку через связь с карточкой. Если оба ещё не связаны с одной карточкой, нужна отдельная операция в Students. Текущие ссылки на новую карточку по INV-6 остаются действующим сценарием. Подключение к существующей карточке описано в [PAR-15…18](students.md#приглашение-родителя-к-существующей-карточке). После выдачи доступа родитель получает то же доступное ученику представление уроков и истории. Действия различаются по LES-34. |

## Подтверждение и перенос

| ID | Правило |
| --- | --- |
| LES-33 | Назначенный урок сразу действует и виден участникам. Назначение, отмена, восстановление, удаление, запись проведённого урока и изменение результата дают обычное уведомление без запроса действия. Согласие требуется только для изменения времени или длительности уже назначенного урока. |
| LES-34 | Предложение преподавателя принимает или отклоняет текущий привязанный ученик. Родитель может видеть предложение, но не принимает его вместо ученика. Если предложение внёс ученик или родитель, решение принимает преподаватель. Согласие автора уже выражено отправкой предложения, дополнительного подтверждения ученика после принятия предложения семьи нет. |
| LES-35 | У предложения переноса есть исходный интервал, новый интервал, автор и состояние. Семья предлагает новое начало одного урока, длительность сохраняется. Преподаватель может предложить новое начало и длительность для одного урока или предложить перенос будущей части серии по LES-23. На каждый затронутый урок допускается одно открытое предложение. Ученик и родитель видят одну запись запроса по карточке, преподаватель получает одно предложение в своём кабинете. Создание запроса и уведомления не повторяется из-за того, что у карточки два участника. Предложение не резервирует время и не меняет календарь. Автор может его отозвать. Участники с текущим доступом видят старое и предложенное время, роль автора и состояние. |
| LES-36 | При принятии сервер проверяет обе стороны, сохранённый состав, прежнее и новое время и конфликты. Для серии ученик принимает один план целиком. Принятие и запись интервалов атомарны. При конфликте предложение остаётся открытым и расписание сохраняется. При отказе или отзыве остаётся прежнее время. Если срок прошёл до ответа, предложение остаётся в истории со статусом «Без ответа» и не меняет урок. Срок заканчивается при наступлении самого раннего из исходных и предложенных начал. Такой запрос больше не блокирует новое предложение. Отмена или удаление затронутого урока и утрата доступа закрывают запрос без переноса. Проверка выполняется и на чтении, и при команде. Перенос одного урока серии создаёт исключение по LES-22. |

## История и удаление

| ID | Правило |
| --- | --- |
| LES-37 | В активном календаре остаются `scheduled`, включая занятия, которым нужна отметка. `completed`, `no_show` и `cancelled` автоматически уходят в представление «История». Это представление текущей записи, без отдельной архивной копии и отдельного действия. Удаление — явная команда преподавателя с подтверждением и проверкой версии. В первом выпуске она удаляет запись, содержимое, связанные запросы переноса, предупреждения о неявке и историю правок из рабочего хранилища. Занятие исчезает из всех календарей и истории, старый адрес отвечает 404. Для ученика и родителя команды удаления нет. |
| LES-38 | Удаление одного занятия серии сохраняет только исключённый порядковый номер в плане. ID удалённого урока и интервал из плана убираются. Серийная правка не создаёт его заново. Совместная транзакция обновляет версию серии и удаляет серию при удалении последней записи. Для защиты от повторной отправки сразу после удаления сохраняется технический маркер на 24 часа. Он содержит срок и отпечаток ключа попытки без ID урока и его содержимого. В этот срок активный владелец получает конфликт на старый ключ создания и использует новый ключ для нового урока. После добавления ДЗ или начислений удаление урока с зависимостями потребует отдельного согласованного сценария. Политика резервных копий применяется отдельно. |

### Исправление записи из истории

- LES-41 [готово] Преподаватель восстанавливает отменённый урок на исходное время, пока оно ещё впереди и свободно. Требуются актуальная версия, активная карточка и подключённый ученик. Сервер проверяет интервал и возвращает тот же урок в `scheduled` одной транзакцией, сохраняет правку и уведомляет семью. У занятия серии остаётся прежняя позиция. Закрытые запросы переноса не открываются. Если время занято или прошло, отменённый урок сохраняется. Интерфейс сообщает причину и даёт открыть черновик нового занятия с той же карточкой, длительностью и содержанием. Преподаватель сам выбирает время и сохраняет новый урок с отдельным ID. История, запросы и связь с серией не копируются.
- LES-42 [готово] Из истории преподаватель может снять ошибочную отметку `completed` или `no_show` с актуальной версии. Тот же урок с прежним интервалом переходит в `scheduled` и появляется в списке «Нужна отметка». Поскольку исходное время закончилось, новая бронь не создаётся. Снятие отметки записывается в историю правок и отражается обычным уведомлением. Для исправления на противоположную отметку действует LES-15.

### Запись проведённого урока задним числом

- LES-43 [готово] Преподаватель может записать фактически проведённый урок для подключённого ученика. Он задаёт фактическое начало, длительность и обычные поля занятия. Окончание должно быть не позже текущего времени. Сервер создаёт обычный урок со статусом `completed`, сохраняет отдельно фактическое время проведения и время регистрации и показывает запись в истории по фактической дате. У урока те же права, ID и команды исправления, что у остальных завершённых уроков. Внешняя площадка не влияет на запись. Финансовый модуль сможет ссылаться на этот ID по своему договору.
- LES-44 [готово] Две отправки одной попытки записи проведённого урока дают одну запись по LES-17. Отдельная подтверждённая попытка сохраняет урок с указанным преподавателем интервалом. Совпадение или пересечение с другой записью автоматически не считается дублем. Преподаватель решает, записать проведённый урок или исправить имеющуюся запись.

## Уведомления в кабинете

LES-39 **[готово]** Обычное уведомление отражает уже выполненное действие. Назначение, отмена, восстановление, удаление, запись проведённого урока, изменение результата и итог запроса переноса видны остальным участникам с действующим доступом. При новом предложении у принимающей стороны есть действие «Принять» или «Отклонить». Другие участники видят предложение без этих действий. После решения устаревшая кнопка исчезает.

LES-40 **[готово]** Изменение и регистрация уведомления фиксируются вместе. Повтор успешно выполненной операции не дублирует уведомление. После отзыва доступа уведомление по карточке недоступно. При удалении прежние уведомления о записи убираются из кабинетов. Новое уведомление об удалении содержит только тип действия и время, без ссылки на урок или копии его полей.

## Предупреждение о неявке и причины действий

- LES-45 [готово] В меню «Изменить расписание» ученик или родитель с действующим доступом выбирает «Предложить перенос» либо «Не сможем прийти». Предупреждение доступно для будущего запланированного занятия и видно обеим сторонам семьи. Преподаватель получает одно уведомление и может отменить урок, предложить перенос или оставить время как есть. Предупреждение само по себе не меняет время, статус и посещаемость. На занятие допускается одно открытое предупреждение. Автор может отозвать его до начала. Принятый перенос, начало, отмена или утрата доступа автором закрывают предупреждение. После закрытия оно остаётся в истории урока, пока доступен сам урок. Удаление урока удаляет предупреждения вместе с ним.
- LES-46 [готово] Поле «Причина» доступно при предложении переноса и предупреждении «Не сможем прийти». Оно необязательно. Предел первой версии — 500 символов простого текста. Причина сохраняется в запросе или предупреждении и видна участникам с доступом к уроку. При принятии переноса повторного ввода нет: основание изменения доступно в истории исходного предложения. Текст не копируется в уведомления и служебные журналы.
- LES-47 [готово] Преподаватель может указать причину при отмене урока или отметке «Пропущен». Действуют те же границы текста и видимости по LES-46. Участники видят причину текущего итога в карточке и истории занятий. Преподаватель также видит причины прежних итогов в истории правок. При восстановлении урока или исправлении отметки прежняя причина перестаёт описывать текущий итог. Отметка «Проведён», удаление и принятие переноса поля причины не требуют и не принимают.
- LES-48 [готово] «Редактировать» позволяет преподавателю-владельцу изменить название, описание, подготовку и закрытую заметку на доступном уроке, включая урок в истории по активной карточке. Сервер проверяет актуальную версию. Урок сохраняет ID, время, длительность, итог, карточку ученика и открытые запросы. При выборе «Только этот урок» правка действует только на него. Для времени и длительности используются команды переноса.

## Когда появляется запись урока серии

- LES-49 [готово] При сохранении серии сервер рассчитывает конечный план с позицией, интервалом и устойчивым `lesson_id` для каждой даты. План хранится компактно в серии и резервирует расписание. Для даты без записи урока календарь и детальный просмотр строят представление из плана и общих полей серии. У всех кабинетов один и тот же ID. Просмотр списка, детали и истории не создаёт записей. История отдельной даты до первого действия пуста, даже если процесс обслуживания уже подготовил запись.
- LES-50 [готово] Успешная изменяющая команда по отдельной дате создаёт запись урока с тем же ID и применяет действие в одной транзакции. Это относится к редактированию, отмене, предложению переноса, предупреждению о неявке и задействованным в будущем связям. Перед записью сервер проверяет роль, связь и версию. Отказ или конфликт не оставляет пустого урока. Если преподаватель удаляет ещё не созданную дату, достаточно отметить позицию исключённой. Она освобождает время, пропадает из календаря и истории и больше не появляется при пересчёте серии.
- LES-51 [готово] При сохранении серии сервер создаёт запись первого ближайшего урока. Обслуживание календаря поддерживает запись ближайшего предстоящего запланированного урока и обрабатывает все наступившие даты без записи, в том числе после простоя. Прошедший урок без отметки остаётся запланированным и требует отметки. Процесс пропускает отменённые, исключённые и недоступные позиции. При отмене или удалении ближайшего запись следующей даты готовится на очередном проходе. Получение записи и пользовательские команды синхронизируются по одной позиции и ограничению уникальности пары «серия, позиция».
- LES-52 [готово] Техническое создание записи само по себе сохраняет уже видимые ID, данные и версию даты. Оно не меняет пользовательскую историю и не отправляет повторное уведомление о назначении. Первое изменение сохраняет своё событие с реальным автором. При переносе всей будущей части серии предложение сохраняет ссылки на позиции, а принятое изменение сохраняет затронутые уроки с теми же ID. Отказ от предложения не меняет план.

## Редактирование серии из урока

- LES-53 [готово] Календарь отмечает урок, принадлежащий серии. Только в таком уроке доступны действия над серией. При сохранении содержания преподаватель выбирает «Только этот урок» или «К будущим урокам серии». По умолчанию выбрано «Только этот урок». Разовый урок сохраняется без этого вопроса. Отдельного редактора шаблонов нет. Дата и длительность по-прежнему меняются через перенос по LES-33…36.
- LES-54 [готово] Содержание шаблона включает название, описание, подготовку и закрытую заметку. При выборе «Только этот урок» фактически изменённое содержание сохраняется как отдельное для этой даты, которая остаётся частью серии. Само создание записи, просмотр, предложение переноса или изменение времени наследование содержания не меняют. При выборе «К будущим урокам серии» форма показывает текущий общий шаблон, переносит в него только явно изменённые поля и показывает число затронутых дат. Сервер меняет шаблон для будущих запланированных уроков без собственного содержания. Изменение времени отдельной даты не исключает её из наследования. Прошедшие, начавшиеся, отменённые и имеющие собственное содержание уроки сохраняют прежний текст. Для прошлого сервер сохраняет версию содержания на момент начала или на более ранний момент отмены. Изменение шаблона обновляет версии затронутых дат без создания записей будущих уроков. Устаревшая открытая форма получает конфликт версии. Семейные представления по-прежнему скрывают закрытую заметку.
- LES-55 [готово] В меню серийного урока преподаватель может выбрать «Отменить все будущие уроки серии». Интерфейс показывает даты до подтверждения. Команда отменяет все ещё не начавшиеся запланированные даты серии, включая уроки с собственным содержанием или вручную изменённым временем. Время освобождается, каждая отменённая дата остаётся в истории по LES-13. Удалённые ранее даты не возвращаются, начавшиеся и прошедшие уроки сохраняются. Действуют актуальная версия серии и общая атомарность LES-25.

## Лента одного урока

- LES-56 [готово] Преподаватель, ученик и родитель с действующим доступом видят общую хронологию событий урока. В ней видны видимое действие, роль автора и время. Перенос показывает исходный и новый интервалы, причины доступны в исходном запросе или предупреждении. Правка содержания перечисляет изменённые общие поля без копий прошлых текстов. Записи о закрытых заметках видит только преподаватель. Семейная лента не хранит копии служебной истории. Когда появятся материалы, лента сможет отображать события добавления и удаления. При удалении урока его лента также удаляется.

### Сквозной пример

Преподаватель назначает «Дроби» на вторник в 17:00. Ученик и родитель сразу видят урок и получают уведомление. Преподаватель предлагает среду в 18:00. В календаре всё ещё стоит вторник. Ученик принимает предложение, и тот же урок для всех перемещается на среду. Если среду предложил родитель, одним действием её принимает преподаватель. Когда урок проведён, он переходит в историю.

### Границы дальнейших решений

- План серии резервирует все интервалы и позволяет заранее проверить пересечения. Отдельная запись урока нужна для изменений, посещаемости и последующих связей с ДЗ и оплатами. Ограниченная длина серии удерживает объём проверок и пакетных команд в предсказуемых границах.
- Для разового занятия хранится момент UTC. Для серии дополнительно хранится выбранная зона и рассчитанный план. Это сохраняет привычный локальный час при смене смещения и позволяет просматривать будущие даты без записи в БД.
- Денежное значение отмены и пропуска согласуется при проектировании Billing. Сроки хранения уроков и истории подтверждает оператор перед публичным запуском.
