# ADR — Аккаунт и восстановление

## IDN

- IDN-5 [готово] Секреты входа не сохраняются открытым текстом. Защита от перебора и утечки действует независимо от выбора способа входа.
- IDN-6 [готово] Сессия серверная, cookie защищена; anonymous CSRF context не предоставляет прав вошедшего пользователя.
- IDN-7 [готово] Изменения через API требуют действующий CSRF; успешный вход заменяет контекст сессии.
- IDN-8 [готово] Пользователь читает и отзывает только собственные сессии; logout прекращает текущую, revoke-all — все.
- IDN-9 [готово] Сброс пароля одноразовый, не раскрывает существование аккаунта, отзывает сессии и не выполняет автоматический вход.
- IDN-10 [готово] Преподаватель и родитель не могут использовать обычный вход от имени ученика или менять его учётные данные.
- IDN-12 [предложено] Деактивация прекращает вход и доступ аккаунта; это отдельно от физического удаления персональных данных.
- IDN-13 [готово] Аккаунт имеет стабильный ID и хранит служебное состояние и данные входа. У аккаунта один личный профиль с изменяемым отображаемым именем и часовым поясом; пользователь редактирует только свой профиль.
- IDN-14 [готово] Для обычного входа нужен один подтверждённый контакт: email или телефон; второго не требуется. Повторная регистрация того же контакта не создаёт второй аккаунт и не меняет данные входа или связи. Подключение внешних OAuth-провайдеров отложено.
- IDN-15 [готово] Путь «Попробовать как репетитор» ведёт к регистрации или входу; пользователь осознанно включает кабинет преподавателя. Первые ученическая и родительская связи появляются по приглашению, с новым или существующим аккаунтом.
- IDN-16 [готово] Регистрация создаёт активный аккаунт и профиль только при одноразовом подтверждении контакта. Используется код со сроком и лимитом попыток. При входе проверяется пароль; ошибки входа одинаковы для неизвестного контакта и неверного пароля.
- IDN-17 [готово] Самостоятельная регистрация доступна на пути преподавателя. Для пути по приглашению действующая ссылка проверяется при запросе и подтверждении кода. Подтверждение не погашает приглашение и не выдаёт учебные права.
- IDN-18 [готово] Запрос восстановления для существующего контакта отправляет одноразовый код. Успешный сброс пароля отзывает все сессии и не меняет профиль и связи.

Снятые ID: IDN-1, IDN-2, IDN-3, IDN-4, IDN-11. Номера зарезервированы.

- IDN-19 [готово] Запрос восстановления возвращает тот же 202 и тот же формат для существующего и неизвестного логина. Код отправляется только по подходящему подтверждённому контакту. Доставка запускается после фиксации короткоживущей записи и не влияет на ответ. Повторный запрос сброса аннулирует прежний код.
- IDN-20 [готово] Dev доставляет email через SMTP в локальный Mailpit, а телефонный код в закрытый SMS inbox. Prod использует SMTP с TLS и SMSC по HTTPS. Ответ API и ответ SMSC о постановке в очередь не обещают доставки. Вход принимает логин и пароль. Логином служит email или телефон, отдельных имён для входа взрослых нет.

Открыты смена контакта, восстановление при утрате доступа к нему и отдельная модель детского входа. HTTP-формы описаны в [API](../api/identity.md).

## Почему так устроено

Стабильный `account_id` и отдельный профиль отделяют вход от кабинетов и связей. Уникальный нормализованный логин включает тип контакта. Email приводится к единому виду после синтаксической проверки. Телефон хранится в международном формате. В браузере из номера убираются пробелы, скобки и дефисы. Профиль содержит имя и часовой пояс IANA. Кабинет репетитора включается отдельно.

Подтверждение использует случайный восьмизначный код на 10 минут, максимум пять неверных попыток. Код сохраняется как HMAC с ID запроса и назначением. У регистрации по приглашению проверяется та же ссылка при запросе и завершении. Регистрация не меняет существующий аккаунт. Сброс связан с ID аккаунта, поэтому повторно сохранять его логин в запросе сброса не нужно. Новый пароль хранится только как Argon2id. Новый пароль и отзыв всех сессий фиксируются атомарно. Пользователь входит заново.

Серверная сессия нужна для немедленного отзыва. Абсолютный срок 7 суток, срок бездействия 24 часа, анонимный контекст 30 минут, максимум 10 активных сессий. Cookie prod использует `__Host-`, Secure, HttpOnly, SameSite=Lax, Path=/ без Domain. Мутации и preview требуют CSRF. После входа контекст меняется. [Хранение и очистка](privacy.md)

Для SMS выбран SMSC с API-ключом, параметрами в теле POST и TLS. Прямой адаптер на стандартной библиотеке сокращает зависимости. SMSC получает только номер, технический код и данные аккаунта отправителя. Его принятие запроса означает постановку сообщения в обработку. В автоматических тестах провайдер заменён имитацией HTTP-ответа. [SMSC HTTP/HTTPS](https://smsc.ru/api/http/)

При запросе регистрации на уже зарегистрированный логин или сбросе для неизвестного логина запись не создаётся. Внешний ответ не зависит от возможности отправки. Реальная доставка начинается после коммита. При сбое доставки или процесса пользователь может запросить новый код. Постоянной очереди с открытыми кодами нет.
