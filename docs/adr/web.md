# ADR — Веб-интерфейс

Правила интерфейса на React: главная, регистрация, кабинет репетитора. Стек и причины — [платформа](platform.md), API — [контракт](../api/README.md).

- Демо-сборка (`VITE_DEMO=1`) целиком работает на тестовых данных — для показа и разработки интерфейса. В рабочей сборке разделы, для которых в API пока нет маршрутов (оплаты, финансы, задания, проверка, тренажёр, отчёты), показывают пометку «скоро», а не тестовые данные. Правила таких разделов проверены тестами интерфейса, но не сервером.
- Где модель интерфейса расходится с API (приглашения, статусы ученика, серии занятий), действует ADR модуля ([students](students.md), [lessons](lessons.md), [identity](identity.md)); правило интерфейса приводится к нему при подключении API.

## Главная по референсу

- MAIN-1 [готово] Главная кабинета преподавателя следует `TutorFlow_Main_Reference.png`: единое полотно с общим фоном расписания (мягкие размытые цветовые пятна, по последнему уточнению владельца), три показателя в общей светлой панели с разделителями (последнее уточнение владельца), timeline занятий и правая колонка внимания/нагрузки. По уточнению владельца сохранены Manrope/Unbounded и более свободные интервалы. Фон расписания на главной приглушён белой вуалью, второстепенные подписи темнее для читаемости. Стиль ограничен маршрутом главной; другие разделы сохраняются.
- MAIN-2 [готово] На главной отсутствуют метрика задолженности, метки долга в занятиях и уведомления вида debt. Счётчик внимания показывает фактически видимые элементы после исключения задолженности и скрытых элементов; пустой список показывает существующее пустое состояние. Финансовые данные и правила других разделов не меняются.
- MAIN-3 [готово] Даты берутся из текущего источника расписания (в демо — демонстрационная дата, в API — часовой пояс профиля); существующие обработчики сохраняются. Рабочая сборка не подменяется демонстрационными данными. Отсутствующие API/действия не выдаются за реализованные: демо-вход в урок остаётся уведомлением о недоступном действии.

## Обзор преподавателя

- OVERVIEW-1 [готово] Верхняя панель кабинета показывает дату из того же источника, что расписание, вместо поиска; под приветствием обзора дата не дублируется.
- OVERVIEW-2 [готово] В обзоре нет кнопок создания задания и урока и блока экзаменов; занятия имеют видимый заголовок «Ближайшие занятия», переключатель дня сохраняется, ссылки «Расписание» внутри блока нет.
- OVERVIEW-3 [готово] «Нагрузка недели» показывает количество уроков, процент загрузки, распределение по дням с выделением сегодняшнего дня и свободные окна; кнопки «Поделиться» нет. Расчёты остаются прежними.
- OVERVIEW-4 [готово] Клик по уроку в «Ближайших занятиях» — сегодняшнему, завтрашнему или ближайшему крупному — открывает карточку урока, как в расписании.
- OVERVIEW-5 [готово] Прошедший сегодняшний урок не считается проведённым сам по себе: у него кнопка «Отметить», после нажатия — галочка «Проведён». Пока нет сервера, отметка живёт до перезагрузки страницы.
- OVERVIEW-6 [готово] Если сегодня уроков нет, блок пишет «Сегодня уроков нет» и показывает до трёх ближайших свободных окон недели; окно ведёт на этот день в расписании.
- OVERVIEW-7 [готово] Пункты «Требует внимания» ведут к объекту: работы — в «Проверку», долг, пакет и «не занимается» — в карточку ученика; «Отметьте урок» отмечает урок. На широком экране пункт можно скрыть до перезагрузки страницы. На узком экране кнопка стоит справа от текста, без кнопки «скрыть».
- OVERVIEW-8 [готово] Столбец «Нагрузки недели» — ссылка на этот день в расписании (вид «День»).
- OVERVIEW-9 [готово] OVERVIEW-1…8 — демо-сборка. В рабочей обзор строится из уроков API: «Ближайшие занятия» (оставшиеся сегодня и завтра), «Нужна отметка» (прошедшие запланированные уроки за две недели, новые сверху) и «Эта неделя» (запланировано, проведено, не пришли, отменено). Клик по уроку открывает ту же панель урока, что в расписании; без учеников — приглашение перейти к ученикам.

Верхняя служебная панель во всех разделах — часть полотна страницы, без нижней границы, отдельной подложки и тени, как на главной. Навигация и счётчик проверки сохраняются.

## Панель урока

- LESSON-UI-1 [готово] Правая панель по `TutorFlow_Lesson_Modal_Reference.png`: светлая поверхность, дата, крупный интервал времени, осмысленный отсчёт, ссылка на ученика, реальные статусы, данные занятия и закреплённые действия. Баланс — только сверху и только при наличии данных; нулевой баланс не означает «Оплачено». Показатели количества и длительности исключены. В API-версии сохраняются формы содержания, предложения переноса, отмены, посещаемости и истории. При отсутствии API материалов кнопка загрузки недоступна с объяснением; не имитируется загрузка и не создаются маршруты. Демонстрационные сведения прошлого урока/карточки ученика подписываются по источнику. Это заменяет оформление панели VIBE-17; действия и права сохраняются.

## Расписание

Источник — [UX-ревью кабинета](../archive/cabinet-ux-review.md); задача — [schedule-new-lesson](../tasks/schedule-new-lesson.md).

- SCHEDULE-1 [готово] Новый урок создаётся в одной панели, которая открывается из «+ Урок», клика по пустому месту недели (дата и время с шагом 15 минут), свободного окна и «+ Урок» в карточке ученика; подставляется всё известное (дата, время, ученик, его длительность).
- SCHEDULE-2 [готово] Панель требует ученика, дату не в прошлом, длительность 15–240 минут, урок в пределах суток; при повторе — хотя бы один день недели и конечную дату не раньше начала. Пересечения с другими уроками показываются предупреждением, но не запрещают создание (бывают сознательные накладки). Итог серии виден до создания: дни, время, число уроков и дата окончания.
- SCHEDULE-3 [готово] Созданные уроки сразу видны во всех видах расписания и в обзоре. Пока нет сервера, они хранятся в памяти до перезагрузки страницы.
- SCHEDULE-4 [готово] Свободные окна в недельном виде видны всегда, а не только при наведении.
- SCHEDULE-5 [готово] Действия в карточке урока зависят от времени: до начала — «Войти», «Перенести», «Отменить»; во время урока — «Войти» и «Проведён»; после конца — только «Проведён». «Войти» открывает ссылку на встречу, если она задана. Из карточки урока есть переход в карточку ученика.
- SCHEDULE-6 [готово] В виде «День» нет вкладок «Сегодня / Завтра» — дни листаются стрелками в шапке. В месяце на широком экране в ячейке до трёх уроков с временем и именем и «ещё N», на узком — цветные точки. В строке урока крупно начало, мелко длительность. На телефоне фильтры свёрнуты за кнопкой «Фильтры» (с числом активных), «+ Урок» — плавающая кнопка, а «Сегодня» скрыта, если сегодняшний день уже на экране.
- SCHEDULE-7 [готово] SCHEDULE-1…6 — демо-сборка. Рабочая показывает те же виды (день, неделя, месяц, список) по [lessons](../api/lessons.md): окно вида запрашивается как UTC-интервал от полуночи до полуночи в зоне профиля, время уроков показывается в зоне профиля. Сетка дня — 9:00–21:00 и расширяется под уроки вне её.
- SCHEDULE-8 [готово] Отменённый урок остаётся в днях, неделе и списке перечёркнутым, не занимает время в свободных окнах и не показывается в месяце; в подписи урока — тема и итог («Проведён», «Не пришёл», «Отменён»).
- SCHEDULE-9 [готово] Панель урока: до начала — «Отменить урок» с необязательной причиной; во время урока — подсказка, что отметить можно после окончания; после окончания — «Проведён» или «Не пришёл» с причиной; у отмеченного — «Снять отметку», у отменённого — «Восстановить урок». При конфликте версии или состояния расписание перезагружается.
- SCHEDULE-10 [готово] Новый урок: ученик (только принявшие приглашение), тема, дата не в прошлом, время, длительность 15–240 минут; «Повторять каждую неделю» создаёт серию из 2–26 уроков, «Проверить даты» показывает занятые даты по предпросмотру сервера. Повтор тех же данных после потерянного ответа идёт с тем же `client_request_id`.
- SCHEDULE-11 [готово] Рабочая сборка следует логике интерфейса бэкенда (`frontend/src/schedule.ts` ветки dev) и [API занятий](../api/lessons.md). Карточка урока: «Перенести» — предложение ученику или родителю (расписание меняется после согласия): «Только этот урок» или «Этот и следующие» (у урока серии, не исключения) с серверным предпросмотром дат и пересечений; «Изменить» — тема, описание, подготовка, закрытая заметка, у серии — «только к этому уроку» или «к будущим урокам серии» с числом затронутых; «Отменить серию» — все будущие или этот и следующие, со списком дат; «Удалить» — с `If-Match` версии; «Снять отметку» у проведённого и пропущенного; «Восстановить» — только у ещё не начавшегося отменённого.
- SCHEDULE-12 [готово] В карточке урока репетитора — «Предложения переноса» (кто, «было → станет», причина; «Принять» и «Отклонить» или «Отозвать» — по флагам сервера `can_resolve` и `can_withdraw`), «Предупреждения о неявке» и «История урока». Подписи ролей, состояний и событий — как у бэкенда.
- SCHEDULE-13 [готово] Новый урок: «Урок уже прошёл — записать проведённым» — разовый урок в прошлом через `record-completed`; повтор серии при этом недоступен.
- SCHEDULE-14 [готово] Кабинет ученика и родителя: под карточками — «Расписание» по неделям (уроки всех карточек, состояние; после окончания без отметки — «Отметки пока нет»). В уроке — подготовка и описание; у будущего урока — «Предложить перенос» (новое время, причина; длительность — как у урока) и «Не сможем прийти» (предупреждение — не отмена); ниже — предложения переноса (ответить репетитору или отозвать своё), предупреждения и события урока.

## Ученики

Источник — [UX-ревью кабинета](../archive/cabinet-ux-review.md); задача — [students-actions](../tasks/students-actions.md).

- STUDENTS-1 [готово] В таблице учеников главное: ученик (имя, цель, метка «не подключён»), расписание (дни и время), следующий урок, последнее ДЗ («Не сдано» или «9 из 10») и оплата. Оплата — «Долг» с подписью «за N уроков», «Оплачено вперёд» с подписью «хватит на N уроков» или «Всё оплачено»; если пакет заканчивается — «в пакете 1 урок». Тариф, контакты и история — в карточке ученика.
- STUDENTS-2 [готово] «Пригласить» открывает окно нового ученика: имя обязательно, цель и контакт родителя — нет; тариф поурочный (цена за урок) или абонемент (число уроков и цена). Ученик сразу появляется в «Активных» с меткой «не подключён», не дожидаясь регистрации. После добавления показываются ссылка-приглашение («Скопировать», «Отправить в Telegram») и кнопка «Поставить первый урок».
- STUDENTS-3 [готово] «+ Оплата» в карточке записывает сумму, способ и дату: баланс ученика пересчитывается сразу, оплата появляется первой во вкладке «Оплаты».
- STUDENTS-4 [готово] Через «Ещё» ученика можно поставить на паузу, отправить в архив или вернуть в активные; удаление — только после подтверждения.
- STUDENTS-5 [готово] Прошедший урок в истории ученика открывает карточку урока, если урок есть в расписании. Во вкладке «Заметки» можно добавить заметку — к ней ставится сегодняшняя дата. Если у ученика нет расписания, вместо «Не задано» — кнопка «Назначить расписание» (новый урок с повтором по дням недели).
- STUDENTS-6 [готово] STUDENTS-1…5 — поведение демо-сборки (`VITE_DEMO=1`): ученики, оплаты, заметки и смена статуса хранятся в памяти до перезагрузки страницы.

- STUDENTS-13 [готово] Карточка ученика открывается окном на весь экран (на компьютере — с отступом 16px, на телефоне — целиком). В шапке имя, цель, статус, Telegram и действия: «Урок», «Оплата», «Задание», «Материал», «Ещё». Слева — сводка карточками: следующий урок с днями недели и длительностью, оплата (статус баланса, тариф, проведено), экзамен (кольцо готовности, дни до экзамена, слабые номера), контакты (родитель с кнопкой звонка, откуда пришёл, Telegram). Справа — вкладки с подчёркиванием, иконками и счётчиками: «Обзор», «Уроки», «Задания» (в работе), «Материалы» (сколько), «Оплаты» (красная точка при долге), «Заметки» (сколько). На телефоне действия — одной строкой с прокруткой, сводка — в начале «Обзора». Без повторов: долг, абонемент и Telegram видны в шапке и сводке, поэтому в «Обзоре» их предупреждений нет (остаются «просрочено» и «на проверке»); «Успеваемость» стоит рядом с последней заметкой, график — с трёх проверенных работ; разделы на всю ширину, вкладки, заголовки и строки — крупнее.
- STUDENT-OVERVIEW-1 [готово] Обзор карточки ученика: четыре карточки — ключевые показатели, оплата, ближайший урок и контакты — без боковой сводки и повторов разделов. Под именем только текущая цель; действия и вкладки сохранены. Период 14/31 день ограничивает текущую историю уроков и домашних работ, включая обе границы и исключая будущее; формулы посещаемости, среднего ДЗ и динамики не меняются. По уточнению владельца обзор чуть компактнее: меньшие заголовки и значения по существующей шкале, кольцо 132 px, уменьшенные поля/иконки и высоты четырёх карточек; шапка и другие вкладки сохраняют размер.

## Задания

Раздел работает в демо-сборке: маршрутов API для заданий пока нет, черновик, банк и диалог живут в памяти. Демо-репетитор ведёт русский язык: ученики, уроки, домашки, прогресс, тренажёр, вариант и проверка сочинений — по русскому; банк и ИИ-помощник открываются на нём.

- TASKS-1 [готово] Задача — единый формат для всех предметов: предмет, экзамен и номер (из каталога экзамена), тема, сложность 1–3, источник (банк ФИПИ, демоверсия, ИИ, своя), условие, тип ответа, баллы и «ответ проверен». Типы ответа: число, слово, выбор (один или несколько), соответствие — проверяются автоматически; развёрнутый — проверяет репетитор по критериям. Число сравнивается без учёта запятой или точки и вида минуса, слово — без регистра, «ё» и пробелов.
- TASKS-2 [готово] Черновик — одна «корзина» на раздел, до 30 задач: наполняется из банка, от ИИ и из сохранённых заданий; в нём меняют порядок, заменяют задачу на другую того же номера (или аналог) и убирают. Сводка: число задач, баллы, примерное время, сколько задач с автопроверкой. На вкладках «Банк» и «Мои задания» внизу — плашка «Черновик · N задач» со ссылкой на сборку.
- TASKS-3 [готово] ИИ-помощник умеет: подобрать задачи из банка по предмету, экзамену, номеру, теме и сложности; сделать аналоги с новыми числами и проверенным вычислением ответом (только вычислимые предметы — математика, физика, информатика); править черновик командами («замени №2», «сложнее», «проще», «перемешай», «очисти»); собрать работу над ошибками ученика по темам его ошибок; проверить, подходит ли черновик для теста. Ограничения: ничего не выдаёт ученикам — только меняет черновик (каждое изменение можно отменить); задачи ИИ помечены; чертежи и тексты — только из банка; на посторонние вопросы вежливо отказывает; имя ученика в запрос к модели не уходит. Параметры подбора — чипами над полем ввода, Enter отправляет, Shift+Enter — перенос.
- TASKS-4 [готово] Банк: предмет → экзамен → номер (под номером — сколько задач) → задачи с фильтром по сложности; у задачи «В черновик» / «В черновике», у номера «+5 случайных» и «Аналоги с ИИ» (если задача вычислимая). Стартовый банк для демо — русский язык (ЕГЭ №1–27 и ОГЭ: по 2–3 задачи с автопроверкой на номер и сочинения), математика (ЕГЭ профиль, ОГЭ), физика, информатика, обществознание, английский.
- TASKS-5 [готово] Из черновика — «Сохранить как задание» (на платформе или распечатка с фото решения) или «Сохранить как тест» (только на платформе; режим «Тренировка» — проверка сразу после ответа, по умолчанию, или «Контроль» — результат в конце; время и число попыток). Тест берёт только задачи с автопроверкой и проверенным ответом: если есть другие, окно называет их и предлагает «Убрать N и сохранить тест» или сохранить как задание. «Сохранить и выдать» сразу открывает выдачу.
- TASKS-6 [готово] «Выдать» — одно окно для задания и теста: кому (поиск, несколько учеников), срок не раньше сегодня, когда показать ответы (сразу, после срока, после проверки). Есть в «Моих заданиях» и после сохранения; «+ Задание» в карточке ученика сначала предлагает выбрать работу из «Моих заданий» и подставляет этого ученика. Выданное сразу появляется в мониторинге ученика («К выполнению», затем результат и ошибки).
- TASKS-7 [готово] «Мои задания» — список заданий и тестов с фильтром: тип, состав, настройки, кому выдано и средний результат; действия «Выдать», «PDF», «В черновик» (собрать новое на основе старого), «Результаты» (по ученикам: срок, статус, процент), удалить.
- TASKS-8 [готово] У ученика на странице «Задания» — блок «От репетитора»: выданные задания и тесты со сроком, статусом и результатом; «Начать тест», «Решать», «Ещё попытка» (если остались попытки), «Распечатать» у задания. Решение — окно на весь экран: точки задач сверху (есть ответ, без ответа, «вернусь позже», верно/неверно), одна задача на экране, поле под тип ответа (крупное поле числа с подсказкой про запятую, плитки выбора, соответствие кнопками, фото решения для развёрнутого), таймер при ограничении времени (по окончании ответы отправляются сами). В тренировке «Проверить» сразу показывает «Верно!» или правильный ответ и разбор; в контроле и задании — итог в конце, перед завершением с пустыми ответами — предупреждение. Итог: процент, верные из автопроверяемых, баллы, время, «ждут проверки», разбор (правильные ответы — по настройке «Когда показать ответы»), «Потренировать похожие». Результат сразу виден репетитору в мониторинге и в «Моих заданиях».
- TASKS-9 [готово] PDF — один шаблон A4 для всех предметов, через печать браузера («Сохранить как PDF»): шапка (TutorFlow, название, «Сдать до», состав, баллы, время), поля «Фамилия, имя», «Дата», «Вариант», инструкция, задачи с местом в экзамене и баллами; у кратких ответов — клетки, у выбора и соответствия — варианты списком, у развёрнутых — линии под решение; внизу — «Сдать онлайн» и номер страницы. Варианты: «Для ученика», «С ответами» (ответы и критерии, без полей ученика), «Бланк ответов» (номера и клетки). Есть в черновике, в «Моих заданиях» и у ученика («Распечатать» — без варианта с ответами). Стили листа — файлом сборки (CSP), на экране лист скрыт.

- TASKS-UI-1 [готово] Учебные страницы используют прежнюю общую оболочку с изолированным оформлением. На «Заданиях» остаются три вкладки. Сборка — две равные панели: чат с постоянными подсказками и параметрами, черновик с отдельным заголовком, редактируемой темой, сводкой и прежними действиями. Списки прокручиваются независимо, ввод и нижние действия доступны. Содержание задач и ответы не подменяются референсом. Чат — существующее демо, без заявления о подключении внешней модели. Очистка черновика требует подтверждения; сохранение/выдача/печать используют прежние обработчики.

## Финансы

Демо-сборка: маршрутов API для оплат нет. Учёт — баланс ученика: проведённый урок списывает его цену (или урок абонемента), записанная оплата пополняет баланс.

- FINANCE-1 [готово] Вверху четыре числа месяца: «Получено» (с изменением к прошлому месяцу и числом оплат), «Ожидается» (оставшиеся поурочные уроки и долги), «Должны» (красным, число учеников), «Оплачено вперёд» (на сколько уроков). Без отдельной героической карточки и графика-дубля.
- FINANCE-2 [готово] «Доход по месяцам» — столбики за полгода: «получено», у текущего месяца сверху светлее «ожидается»; значения — в подсказке, подписан выбранный месяц; нажатие открывает месяц. Под графиком — средний месяц, лучший месяц и число уроков.
- FINANCE-3 [готово] «Долги и абонементы» — должники («Оплатил» записывает оплату, «Напомнить») и заканчивающиеся абонементы («Продлить»). «Кто платил» — ученики по сумме оплат за месяц полосками. «Операции» — во всю ширину, с фильтром и поиском.
- FINANCE-4 [готово] «+ Оплата» — выбор ученика и то же окно, что в карточке ученика (сумма, способ, дата не в будущем). Записанная оплата сразу видна в балансе, «Получено», «Кто платил» и «Операциях».

- FINANCE-UI-1 [готово] Финансы по утверждённому `TutorFlow_Finance_Reference.png`: три компактных KPI («Получено», «Ожидается», «Проблемные оплаты»), две карточки («Доход по месяцам» и «Что требует внимания»), затем единые «Операции». Убраны отдельные «Оплачено вперёд», «Кто платил» и лучший месяц; средний месяц, число уроков выбранного месяца и средний чек сохраняют прежние формулы. Все суммы, фильтры, маршруты и запись оплаты — из существующей модели. Внимание: сначала текущие долги, затем заканчивающиеся абонементы, затем число предстоящих поурочных уроков выбранного месяца; не выдавать прогноз уроков за события оплаты и не придумывать недельную статистику. На странице максимум три строки, полный список и прежнее массовое действие доступны в диалоге. Демонстрационные отметки напоминаний/продления явно не обещают отправку сообщения или изменение абонемента. Скрытые операции не остаются в дереве доступности. Оболочка главной применяется только к финансам, разделитель в финансах выровнен по единой ширине бокового меню; остальные страницы сохраняют оформление. Это заменяет композицию FINANCE-1…3 и VIBE-8 только в финансах; данные и FINANCE-4 сохраняются.

## Проверка

Очередь строится из сданных работ («Мои задания» → выдача → попытка ученика); краткие ответы уже проверены автоматически.

- REVIEW-1 [готово] Слева панель «Задания / Тесты» с числом работ, ждущих проверки; внутри — работы (с непроверенными сверху, «ждут: N») и ученики со статусом («Не сдано», «Ждёт проверки», «Проверено», процент). Число у «Проверки» в меню — сколько работ ждут.
- REVIEW-2 [готово] Справа окно работы: ученик, название, когда сдано и сколько решал; «Автопроверка» — «N из M верно», квадратики задач и раскрываемый список ответов (ответ ученика и верный).
- REVIEW-3 [готово] Развёрнутая задача: условие, раскрываемые критерии, решение ученика (фото/распознанные строки). ИИ не проверяет сам: «Проверить с ИИ» — сверка с критериями, предложенный балл, что сделано и что нет, подсветка строки с ошибкой; «Взять оценку ИИ» подставляет балл и комментарий, если ИИ не уверен — честно просит проверить вручную.
- REVIEW-4 [готово] Оценка — за репетитором: баллы кнопками (0…максимум), комментарий, «Засчитать N из M» или «Вернуть на доработку» (только с комментарием). Когда непроверенных задач не осталось, работа «Проверено» и попадает в мониторинг ученика; возвращённую ученик видит с комментарием и сдаёт заново.

- REVIEW-UI-1 [готово] Проверка по референсу: заголовок без подзаголовка, очередь около 28% и единая правая панель. Сохраняются группировка работ, реальные статусы, вкладки, автопроверка, критерии и прежние действия преподавателя. ИИ предлагает, применение предложения меняет только черновик, итоговая оценка — отдельное явное действие через прежний обработчик. Балл, комментарий и предложение ИИ хранятся в памяти кабинета отдельно по выдаче, попытке и задаче, переживают навигацию, очищаются после оценки/возврата; сохранение черновика не меняет библиотеку или статус. Нет фиктивного сохранения на сервере. Распознанные строки из существующей демо-модели подписываются как демо; при отсутствии оригиналов не изображать работающий просмотр фотографий и не подменять файлы выдуманным OCR. Существующие файлы с доступным URL открываются отдельно. Результат ИИ краткий, подробности скрыты по умолчанию, предусмотрены запуск/ожидание/повтор после ошибки. API и правила REVIEW-1…4 не меняются.

## Кабинет ученика

Демо-сборка; данные — выданное репетитором («Мои задания»), журнал тренажёра и стартовая история.

- STUDENT-1 [готово] Прогресс зависит от цели ученика. Готовится к экзамену (ЕГЭ/ОГЭ) — освоение по номерам экзамена, «готовность» (точность, взвешенная по первичным баллам; непройденное — ноль) и прогноз первичных баллов. Занимается по программе — освоение по темам, без экзаменационных баллов. Уровень: от трёх ответов; ≥85% — «освоено», ≥70% — «хорошо», ≥50% — «средне», иначе «слабо». Данные: тренажёр, проверенные задания и тесты, стартовая история.
- STUDENT-2 [готово] Главная: приветствие и цель (экзамен и дни до него или программа), мини-мониторинг — «решено за неделю» и «точность» — и «Тренироваться»; «Ближайший урок», «Сейчас в работе» (выданное, не сданное), «Мой прогресс» (готовность, прогноз, освоено), «Подтянуть» (слабые места, «Тренировать» — только если в тренажёре есть задачи), «Новые материалы», «Отзыв репетитора». Опыта, серий и цели дня нет — по решению владельца.
- STUDENT-3 [готово] Раздел «Материалы»: всё, что прислал репетитор, карточками с типом, размером, датой и комментарием; фильтр по типу; «Новое» до первого открытия, открытие отмечается для репетитора.
- STUDENT-4 [готово] «Задания» в живом стиле: группы «Сейчас», «На проверке», «Готово», крупные цветные карточки, объёмные кнопки, кольцо результата. Плеер: полоса прогресса, в тренировке после «Проверить» снизу выезжает зелёная или красная панель с правильным ответом, при ошибке карточка вздрагивает; итог — процент, баллы и время, без опыта. Анимации отключаются при «уменьшить движение».
- STUDENT-5 [готово] Тренажёр: бесконечные задачи с мгновенной проверкой — из банка, затем аналоги с новыми числами; режимы «Слабые места» (по слабым номерам по кругу), «По номеру» (номера без задач автопроверки недоступны), «Мои ошибки» (ошибочные задачи, уходят после верного ответа); сессия из 10 задач и «Пропустить»; каждый ответ идёт в прогресс. Сбоку — мини-мониторинг: решено за неделю, точность, готовность. Комбо, опыта, цели дня и серии нет.
- STUDENT-6 [готово] «Прогресс»: большое кольцо готовности и прогноз, освоено, точность, последний результат; карта номеров (или тем) с цветом уровня и полоской доли верных — нажатие открывает тренажёр по номеру; «Результаты заданий» столбиками; «Что подтянуть» и «Как считается».

## Регистрация и вход

Источник — договор [identity](../api/identity.md) и [ADR Identity](identity.md). Регистрируется репетитор; ученики и родители приходят по приглашению ([students](students.md)).

- SIGNUP-1 [готово] Код регистрации не запрашивается без отмеченного согласия с офертой: показывается «Отметьте согласие с офертой, чтобы продолжить», фокус переходит на чекбокс.
- SIGNUP-2 [готово] Регистрация — по почте или телефону (в международном формате с «+»; пробелы, скобки и дефисы убираются). Код из 8 цифр подтверждает контакт; затем имя и пароль от 15 до 128 символов. Часовой пояс берётся из браузера, без него — UTC. Код, пароль, имя и часовой пояс уходят на сервер одним запросом; входа через Telegram и Google нет.
- SIGNUP-3 [готово] Неверный по формату контакт не отправляется: «Проверьте почту или телефон: телефон — в формате +79991234567».
- SIGNUP-4 [готово] Поле кода принимает только цифры, переносит фокус, понимает вставку и автозаполнение. Неверный или устаревший код выясняется при создании аккаунта и возвращает к вводу кода с пустыми полями.
- SIGNUP-5 [готово] Повторно запросить код можно через 60 секунд; до этого виден таймер. Повторный запрос выдаёт новый код взамен прежнего.
- SIGNUP-6 [готово] Шаг профиля требует имя («Напишите, как к вам обращаться») и пароль нужной длины; ошибки — под своими полями.
- SIGNUP-7 [готово] Вход — по почте или телефону и паролю. Если кабинет репетитора включён, открывается он; иначе предлагается включить. Ошибка входа одна для неизвестного логина и неверного пароля.
- SIGNUP-8 [снято] Хранение версии согласия — вне договора API.
- SIGNUP-9 [снято] Пределы кода (срок, попытки, частота) проверяет сервер по IDN-16, IDN-19.
- SIGNUP-10 [снято] Демо-учеников при регистрации сервер не создаёт.
- SIGNUP-11 [готово] «Забыли пароль?» — код на логин и новый пароль; после смены — снова форма входа с сообщением «Пароль обновлён. Войдите с новым паролем.»

## WEB-INTEGRATION-1 — граница рабочего интерфейса и демонстрации

[готово] При интеграции интерфейса в `dev` сохраняются серверные контракты актуальной `dev`: аккаунты и сессии, приглашения, карточки учеников, занятия и расписание. Рабочая сборка использует существующие API-адаптеры; недоступные серверные возможности остаются заглушками. Полный демонстрационный интерфейс доступен только при `VITE_DEMO=1`, его локальные данные не подменяют ответы сервера.

Причина: сохранить завершённый дизайн владельца и готовые функции второго участника, не выдавая локальные модели финансов, заданий и учебного прогресса за сохранённые серверные данные. Новые контракты, миграции и зависимости для интеграции не нужны. Задача и критерии — [FRONTEND-DEV-1](../tasks/frontend-dev-integration.md).

## WEB-INTEGRATION-2 — ресурсы интерфейса и маршруты SPA

[готово] Caddy отдаёт существующие файлы рабочей сборки по исходным путям, включая `/landing/`, `/favicon.svg` и `/og-image.png`; только отсутствующий файл вне API получает `index.html` для маршрутизации React. Проксирование `/api/v1` сохраняется. Причина: безусловная подмена на `index.html` из прежней конфигурации ломает изображения нового интерфейса при обычном запуске стека.

Проверка: браузерный сценарий проверяет содержимое и тип ресурсов, прямой переход на `/teacher/students` и настоящий API. Решение использует штатный [try_files Caddy](https://caddyserver.com/docs/caddyfile/directives/try_files), без новых зависимостей.
