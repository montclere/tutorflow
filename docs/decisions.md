# decisions

Решения, причины и открытые вопросы.

## INF-1 — устройство репозитория

- Дата: 2026-11-16. Статус: принято в рамках настройки репозитория.
- Папки: backend, frontend, docs, deploy, scripts; скиллы в `.agents/skills`.
- Основа: workflow соседней `forum-nstu-beta`, без её кода, секретов и требований.
- Работа двух участников: отдельные ветки/worktree, задачи от dev, ревью вторым участником, выпуск из main.
- Стек приложения и окружения пока не выбраны.
- Локальная CLI-команда и GitHub Actions запускают одинаковые проверки; настройки Claude не используются.
- CI запускается на push в main и PR в dev. Код или конфигурация модуля без его скрипта проверок блокирует проверку.

## INF-2 — стек frontend

- Дата: 2026-11-17. Статус: принято вместе с первой страницей (регистрация преподавателя).
- Vite 8 + React 19 + TypeScript 6.0, стили — CSS Modules и CSS-переменные из `frontend/src/styles/tokens.css`, тесты — Vitest, линтер — ESLint 9 с typescript-eslint, react-hooks и jsx-a11y.
- Причина: тот же набор уже выбран в ветке `develop`; одностраничному лендингу не нужен SSR. TypeScript 7 не поддерживается typescript-eslint, jsx-a11y не поддерживает ESLint 10 — поэтому версии на шаг ниже последних.
- Маршрутизатора нет: на странице одна точка входа, кабинет `/teacher` откроется отдельным маршрутом, когда появится.
- Шрифты Google Fonts подключаются через `preload` без блокировки отрисовки: с блокирующей таблицей Lighthouse (мобильный) давал производительность 80.
- Проверки: `frontend/scripts/check.sh` (npm ci, lint, типы, тесты, сборка), подключён к `./scripts/dev.sh check` и CI.

## SIGNUP — страница регистрации

- Дата: 2026-11-17. Статус: интерфейс готов, серверной части нет.
- API регистрации — один модуль `frontend/src/features/auth/api` с интерфейсом из [frontend-api](frontend-api.md). Пока сервера нет, рабочая сборка отвечает «Регистрация временно недоступна», а не изображает успех (SIGNUP-8…10 в статусе `[нет]`).
- Заглушка API включается `VITE_AUTH_MOCK=1` только в режиме разработки; условие записано через `import.meta.env.PROD`, поэтому сборщик вырезает её из продакшен-бандла.
- После смены шага мастер ставит фокус на главное поле шага (почта, первая цифра кода, имя), а не на кнопку «Назад»: так быстрее продолжить ввод. На остальных шагах — первый интерактивный элемент.
- Ошибки шага «О себе» показываются под своими полями, а не одной строкой, как в прототипе: поле связано с текстом ошибки через `aria-describedby`.
- Карточка «Александр» в герое скрыта уже на ширине ≤ 860px: на 768px она перекрывала подзаголовок.
- Картинки 3D ищутся в `frontend/public/3d/*.webp` при сборке (плагин `frontend/vite/objects3d.ts`), чтобы браузер не запрашивал отсутствующие файлы. Для «будильника» прототип использует рисунок календаря; отдельной заглушки нет.
- Токены покрывают цвета, шрифты, кегли, радиусы, тени и длительности анимаций. Отступы и позиции декора остаются в CSS-модулях компонентов.
- Ссылки на оферту и политику ведут на `/offer` и `/privacy`; самих страниц нет (вне объёма).
