# TutorFlow

Правила для агентов; инструкция человеку — [docs/workflow.md](docs/workflow.md).

## Перед началом

- Прочитай [spec](docs/spec.md), [stages](docs/stages.md), [behavior](docs/behavior.md), [decisions](docs/decisions.md) и AGENTS.md затронутых папок.
- Прочитай [security](docs/rules/security.md); используй процедуру из `.agents/skills/` по задаче.
- Проверь ветку и `git status`; сохраняй чужие изменения.
- Работай в отдельной ветке и worktree по [workflow](docs/workflow.md); одну задачу ведёт один исполнитель.
- До кода зафиксируй границы задачи, ID правил, критерии готовности и затронутые общие файлы.

## Реализация

- Меняешь поведение: сначала правило с ID в `docs/behavior.md`, затем тест и код.
- Не выдавай заглушки за реализованное поведение; стек и продуктовые требования пока не выбраны.
- Выбирай простейшее решение в рамках задачи; существенное решение записывай в `docs/decisions.md`.
- Уточняй только неоднозначности, влияющие на продукт, внешние контракты или необратимые действия; учитывай уже данное разрешение.
- Держи бизнес-правила вне HTTP-обработчиков и UI; не создавай слои до появления кода.
- Пиши идентификаторы по-английски, документы и сообщения людям по-русски.
- Называй сущности по смыслу; не добавляй абстракции и зависимости без текущей потребности.
- Держи секреты и адреса окружений в переменных окружения; продуктовые пороги — в настройках приложения.
- Добавляя зависимость, используй `add-dependency`; меняя БД — `migration`; исправляя логику — `tdd`.
- Не меняй чужие файлы за пределами задачи; пересечение согласуй с вторым участником через задачу или PR.

## Git и сдача

- Веди задачи от `dev`; используй ветки `<тип>/<участник>/<задача>`; `main` предназначена для выпусков.
- Не делай commit, push, merge, release или deploy без соответствующего поручения; создание локальной рабочей ветки разрешено в рамках задачи.
- Пиши коммиты `тип(область): описание` с кратким описанием по-русски; один коммит — одна законченная единица.
- Проверяй свою задачу и запускай `./scripts/dev.sh check`; исправляй ошибки до сдачи.
- Сообщай, что изменено, какие проверки реально выполнены и что осталось; SKIP не называй пройденным тестом.
- Обновляй задачу и статус в `docs/stages.md`; передавай результат второму участнику на ревью.

## Документы и скиллы

- Храни один факт в одном месте; в README оставляй краткое назначение и ссылки.
- В `AGENTS.md` держи правила и указатели; продуктовые правила — в behavior, причины — в decisions.
- Имена документов пиши строчными через дефис; исключения — стандартные AGENTS.md, README.md, SKILL.md.
- Держи процедуры в `docs/skills/`, входы скиллов в `.agents/skills/<имя>/SKILL.md`; относительные ссылки скилла ведут к процедуре.
