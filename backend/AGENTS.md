# Backend

## Область

- Исходники находятся в [app](app/), проверки — в [tests](tests/), изменения схемы — в [migrations](migrations/), служебные команды — в [scripts](scripts/).
- Для конкретного модуля прочитай его локальные инструкции, доменную модель, публичный контракт и выбранные сценарии. Требования найди через [документацию](../docs/).
- Модуль identity — эталон организации слоёв, прикладных сценариев и явных контрактов. При новой работе выбирай прямую модель для согласованных пользовательских сценариев; не добавляй сложность ради гипотетических редких вариантов, сохраняя обязательные инварианты доступа и данных.

## Границы

- Домен содержит сущности, value objects, исключения, инварианты, бизнес-решения и доменные сервисы. Доменные сценарии выражают бизнес-поведение через явные контракты.
- Application организует доменные шаги, транзакции, часы и внешние порты. Ядро свободно от HTTP, SQLAlchemy, чтения окружения и конкретных адаптеров.
- Операции ожидания в backend асинхронны от HTTP-обработчика до порта хранения или сетевого адаптера. Для БД используй отдельную AsyncSession на транзакцию, для сетевых вызовов — async-клиенты. Блокирующие CPU-вычисления и файловые операции выноси из event loop.
- Infrastructure реализует порты, хранение, транзакции и сетевые вызовы. Репозитории возвращают доменные объекты.
- Presentation разбирает вход, проверяет HTTP-сессию, вызывает сценарий и собирает ответ. Права и инварианты проверяются также в сценарии.
- Модуль владеет своими данными. Межмодульное обращение идёт через публичный контракт.
- Сборка приложения связывает адаптеры с узкими зависимостями маршрутов. Общие примитивы остаются независимыми от бизнес-модулей.
- Закрепляй владение и инварианты подходящими ограничениями БД. Для операций записи определяй поведение при повторе и конкуренции, для списков — границы выборки.
- Изменения схемы оформляй новой миграцией. Проверяй создание с нуля и обновление с существующими данными.
- Логи и ошибки сохраняют ID запроса и исключают чувствительные значения. Labels метрик имеют ограниченный набор значений.
- Настройки окружения разбираются и проверяются через Pydantic Settings при сборке соответствующего компонента. Секретные значения защищай SecretStr или SecretBytes. Домен получает готовые значения и политики без зависимости от Pydantic.
- Прикладной сервис задаёт границу транзакции через Unit of Work. CRUD-репозиторий выполняет операции в переданной сессии. Самостоятельные административные операции могут владеть отдельной транзакцией.
- Доменные сервисы выражают бизнес-решения, которые не принадлежат одной сущности. Прикладные сервисы координируют сценарий, технические адаптеры реализуют внешние механизмы. Не создавай доменный сервис ради названия слоя.
- Группируй реализации по ответственности внутри существующих слоёв, когда файлов становится достаточно для отдельной группы. Структура папок не должна вводить новые бизнес-модули без их собственных границ.
- HTTP-зависимости связывай средствами FastAPI и явной сборкой приложения. Дополнительный DI-контейнер нужен только при конкретной потребности.
- Создавай только используемые файлы и слои. Пустые пакеты для одних импортов не нужны.

## Python

- Первая строка файла — однострочный модульный докстринг с назначением файла. Другие докстринги и комментарии запрещены.
- Группы присваиваний и логические блоки разделяются одной пустой строкой. Это относится к целым условиям, циклам, with, try и return/raise. Связанные ветви if/elif/else, try/except/else/finally, for/else и match образуют один блок без пустых строк между ветвями.
- Самостоятельные функции, классы и соседние конструкции разделяются двумя пустыми строками. После последнего импорта перед кодом — две.
- После модульного докстринга — одна пустая строка, включая случай первой функции или класса. Между методами класса — одна.
- Фиксируй возвращаемые типы. find допускает отсутствие результата, get возвращает объект или ошибку, list — коллекцию. Локальным счётчикам подходят короткие имена.
- Оформление проверяет штатный форматтер. Читаемость, выбор конфигурации и границы домена проверяются при ревью.

## Проверки

- Используй адресные режимы общих [утилит](../scripts/). Связывай тесты с BR-ID в общей карте [тестов](../tests/).
- Доменные правила проверяй без сети, HTTP-контракты и конкурентные операции хранения — на PostgreSQL.
- При добавлении проверки расширяй соответствующий инструмент и регрессионные тесты.
