# Implement Issue

## Вход
- Номер Issue, список BR-ID, критерии приёмки. Проверь зависимости и существующие реализации.
- Загрузи только необходимый фрагмент `docs/business-rules.md`, связанный UC и релевантный код. Не перечитывай весь репозиторий.

## Работа
1. Если нет согласованного входа/ожидаемого результата/прав доступа — останови только заблокированный участок и задай конкретный продуктовый вопрос; остальные независимые задачи можно выполнять.
2. Сформируй короткую внутреннюю матрицу сценариев: success, permission denied, boundary, duplicate/retry/concurrency если применимо. **Проверь, что assertions доказывают именно BR**, а не просто 200/не-null.
3. Добавь тесты, привяжи их к BR-ID в `backend/tests/rule-map.json`. Один targeted RED запуск новых тестов (для действительно нового поведения); не имитируй RED удалением кода и не ломай существующие тесты намеренно.
4. Реализуй минимальный вертикальный функционал — API/домен/хранение/UI при необходимости. Не создавай дополнительные абстракции, если они не нужны issue. Границы модульного монолита соблюдай.
5. После реализации запусти **только** `python3 scripts/check.py rule BR-...`; если падает — исправь и повтори целевой тест. При изменении общего контракта — добавь ближайшие затронутые тесты.
6. Перед PR запусти `python3 scripts/check.py pr` один раз (быстрые статические/контрактные проверки). Полные тесты — CI. При локальном непроходящем PR-check исправь и повтори только упавший этап.
7. Один проход code review: безопасность, изоляция данных, миграции, пропущенные ошибки, корректность assertions. Не запускай отдельные многократные LLM-review по файлам.
8. Проверь diff, создай осмысленный commit и PR с `Closes #N`, BR-ID и кратким evidence. Не закрывай Issue до merge.

## Эффективность
- Скрипты выводят summary, а лог сохраняют в `.artifacts/logs/` (gitignored).
- Не запускай локальный full-suite, если нет особых причин. В CI full-suite обязателен после добавления кода.
- Не утверждай, что правило «проверено», если тест не существует/не выполнился.
- Не меняй business rules ради зелёных тестов.
