# Реализация задачи

## Когда использовать

Изменение поведения, исправление дефекта или самостоятельная техническая работа.

## Вход

Issue или явно согласованный объём, выбранные BR/UC, критерии приёмки и границы порученных Git/GitHub-действий.

## Порядок

1. Прочитай корневые и локальные инструкции затронутой области. Найди требования штатным режимом общих утилит. Открой нужный сценарий, связанные правила, локальный код и ближайшие тесты.
2. Проверь ветку, рабочее дерево, зависимости задачи и существующие реализации. Учитывай поручение работать в текущей ветке.
3. До кода определи ожидаемый результат, положительный и применимые отрицательные исходы, границы, права, повторы и конкуренцию. Уточни только неоднозначности, влияющие на продукт или контракт.
4. Сначала посмотри справку существующих скриптов и переиспользуй подходящую проверку. Новое поведение проверяй адресным тестом, который до исправления воспроизводит отсутствие нужного результата.
5. Реализуй законченный результат с соблюдением локальной архитектуры. При новой зависимости проверь необходимость, совместимость, лицензию и фиксацию версии существующим менеджером пакетов.
6. Для изменения схемы добавь новую миграцию. Проверь ограничения, применение с нуля и обновление с данными. Для существенного технического выбора используй ADR по указателю документов.
7. Свяжи тесты с BR-ID в общей карте выбранной области тестирования. Запусти адресный режим утилит. Повторяй упавшее после исправления, общий контракт проверяй также у ближайших потребителей.
8. Перед сдачей запусти штатные форматирование и PR-проверку. Разовую повторяемую диагностику закрепи в существующем инструменте.
9. При порученной работе с Git собери самостоятельно проверяемые задачи отдельными законченными коммитами. Один поток UC или технической работы собери в PR. Сформируй описание готовым генератором.
10. Переведи выполненные подзадачи в Done после открытия PR. Родительский UC остаётся открытым до merge и проверки сквозного результата.
11. Проведи итоговое ревью по соответствующему скиллу и дождись CI последнего коммита. Готовность PR требует выполнения всех критериев. Частичный результат оформляй черновиком.
12. Выполни порученное слияние merge-коммитом, проверь результат, закрой родителя и удали использованную рабочую ветку.

## Результат

Изменения, реальные проверки и логи, связанные задачи и PR в пределах поручения, оставшиеся ограничения. Локальный полный прогон нужен при конкретной причине, полный CI обязателен перед завершением потока.
