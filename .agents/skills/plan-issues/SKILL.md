# Планирование задач

## Когда использовать

Планирование бэклога, декомпозиция сценария или подготовка готовых задач.

## Вход

Выбранные UC/BR, цель текущего этапа и согласованные ограничения.

## Порядок

1. Прочитай общие правила и локальные инструкции документов. Через справку утилит найди режим поиска требований и загрузи только выбранные UC/BR.
2. Проверь существование ID и связи штатной проверкой документов. Открытые продуктовые вопросы согласуй до планирования зависимой реализации.
3. Проверь существующие Issues и PR. Создай родительский Issue UC и самостоятельные проверяемые подзадачи. У каждой задачи должны быть ожидаемые исходы, границы и проверка результата.
4. Общее правило имеет один источник. Повторное использование связывай зависимостью, а новую работу по правилу ограничивай отдельным результатом.
5. Собери заголовки и описания режимом GitHub-генерации общих утилит. Шаблоны бери из документов по локальным указателям.
6. Подзадачи, зависимости и Development связывай штатными средствами GitHub. Project хранит статус, этап и приоритет. Возможности CLI определяй по справке установленной версии.
7. Создавай внешние задачи в пределах поручения. При недоступном GitHub сохрани подготовленный результат и укажи конкретный отказ.

## Результат

Ссылки на созданные задачи или подготовленные тексты, порядок независимых шагов и конкретные нерешённые вопросы.
