# Планирование задач

## Когда использовать

Планирование бэклога, декомпозиция сценария или подготовка готовых задач.

## Вход

Выбранные UC/BR, цель текущего этапа и согласованные ограничения.

## Порядок

1. Прочитай общие правила и локальные инструкции документов. Через справку утилит найди режим поиска требований и загрузи только выбранные UC/BR.
2. Проверь существование ID и связи штатной проверкой документов. Зафиксируй согласованные ответы в правилах, границы и критерии в UC; оставшиеся вопросы с предлагаемыми вариантами оставь в том же источнике UC. Не записывай предложения как утверждённые решения.
3. Проверь существующие Issues и PR. Создай родительский Issue UC и самостоятельные проверяемые подзадачи. У каждой задачи должны быть ожидаемые исходы, границы и проверка результата.
4. Общее правило имеет один источник. Повторное использование связывай зависимостью, а новую работу по правилу ограничивай отдельным результатом.
5. Собери заголовки и описания режимом GitHub-генерации общих утилит. Шаблоны бери из документов по локальным указателям.
6. Подзадачи, зависимости и Development связывай штатными средствами GitHub. Типы задач, поля и автоматические переходы описаны в [процессе GitHub](../../../.github/). Не добавляй Issues в Project и не повторяй автоматические стадии вручную; проверь, что автоматика сработала. Приоритет и готовность выбирай по задаче.
7. Задачи с нерешённым продуктовым контрактом оставляй в бэклоге. До Ready должны быть определены проверяемый результат и границы. Формируй независимые единицы реализации и порядок по нативным зависимостям; не выдавай создание будущего порта за готовность связанной функции.
8. Создавай внешние задачи в пределах поручения. При недоступном GitHub сохрани подготовленный результат и укажи конкретный отказ.

## Результат

Ссылки на созданные задачи или подготовленные тексты, порядок независимых шагов и конкретные нерешённые вопросы.
