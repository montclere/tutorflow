# migration

Пути к файлам указаны от корня репозитория.

Когда: изменение схемы БД или преобразование данных. Инструмент миграций ещё не выбран.

1. Запиши новое правило и совместимость старого кода с новой схемой.
2. Для работающего окружения разделяй добавление структуры, переключение кода и удаление старой структуры на совместимые выпуски.
3. Сгенерируй миграцию выбранным инструментом, прочитай SQL; применённую миграцию не переписывай.
4. Проверь ограничения, блокировки, индексы и поведение на существующих строках.
5. На отдельной тестовой БД проверь применение с нуля и обновление с предыдущей версии.
6. До рабочей БД опиши резервирование, проверку восстановления и откат кода.
7. Запиши команды и ограничения в README backend и PR; данные и схема живого сервера меняются только по поручению.
