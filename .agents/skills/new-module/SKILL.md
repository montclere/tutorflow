# new-module

Пути к файлам указаны от корня репозитория.

Когда: новая фича или модуль backend. Пути внутри процедуры — от корня репозитория.

1. Прочитай `backend/AGENTS.md`; выбери простой модуль или слои по реальной сложности.
2. Запиши правила в ADR и согласуй контракт в API со вторым участником.
3. Напиши тест на бизнес-правило, затем минимальную реализацию по процедуре tdd.
4. Отдели БД и внешние сервисы от логики; не создавай дополнительные пустые слои сверх согласованного каркаса.
5. Добавь миграцию при изменении схемы, обработку ошибок и проверку прав на каждом объекте.
6. Проверь через API успех, неверный ввод, отсутствие доступа и чужой объект.
7. Подключи проверки модуля к `./scripts/dev.sh check`; обнови ADR, задачу и stages.

Образцы: `backend/app/modules/health` — простой модуль, `students` — полный. Общее ядро — в `backend/app/shared`. Запуск и проверки описаны в README backend.
