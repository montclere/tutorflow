# Review PR

1. Получи diff PR и BR-ID из описания; перечитай только соответствующие правила и код изменённых модулей.
2. Проверь факт реализации правил, права доступа/изоляцию преподавателей, негативные пути, гонки записи (если есть), ошибки/потерю данных, миграции и обратную совместимость.
3. Проверь что test-map содержит BR-ID, тесты проверяют нужный **observable outcome**, не подменены моками всюду и имеют отрицательные сценарии.
4. Используй уже имеющиеся результаты локальных проверок и CI. Не запускай всё заново при зелёном актуальном CI, если не обнаружил конкретный дефект.
5. Верни findings с `severity`, файл/строка, BR-ID и краткой правкой. Без общих рассуждений; если проблем нет — явно укажи отсутствие найденных blockers, но не гарантируй отсутствие всех ошибок.
6. После устранения дефектов дождись CI; PR/Issue завершаются только после merge. Не делай merge самостоятельно без разрешения.
